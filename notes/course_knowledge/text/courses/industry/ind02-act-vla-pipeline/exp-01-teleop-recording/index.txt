02
核心原理：人在环数据流
课段 1 收尾 + 课段 2 · 激活旧知 · 8 min
❓ 聚焦问题（课段 1）
学员现场最常踩的坑：
双臂遥操作启动后从臂一动不动
，或者
录了半小时发现缓存目录里数据集是空的
——明明命令跑完了，episode 数却是 0。问题出在哪？带着这两个故障听完全课，到课段 6 你会亲手让示教数据稳稳落盘。
把机器人想成一双刚学会拿筷子的手：它还不知道"怎么抓"，但人类操作员知道。遥操作就是给人的手上绑一根"提线"——你动主臂（leader），从臂（follower）像镜子一样跟着动，把"抓-拿-放"的完整手艺原样录下来。
整条数据流分三段：
①主从控制
——主臂编码器读出 6 个关节角度，经串口发给从臂执行，循环速率约 60 Hz（日志显示
time: 16.72ms (60 Hz)
）；
②多模态感知
——左右手腕摄像头 + 头部摄像头把
640×480 / 30 fps
画面同时写入；
③数据落盘
——每一帧的机器人状态、动作、任务文本与视频被打包成一个 episode，任务结束后的复位期（reset）不算入有效片段。
存储路径在
~/.cache/huggingface/lerobot/<学生名>/<数据集名>/
。录制暂停时视频还要经过 SVT-AV1 编码（日志出现
Map: 100%|…| 479/479
与
SVT-AV1 Encoder Lib v3.0.0
），此时机械臂不要动，等
Recording episode 1
出现再开始下一条。
为什么强调两套频率：关节指令跑 60 Hz 是为了跟手不滞后，图像停在 30 fps 是为了给编码和落盘留带宽——两者由同一个 episode 时间戳对齐，任何一路掉帧都会让"这一帧该出哪只手"的对应关系错位。
↺ 激活旧知（课段 2）
回忆三条旧知：① 串口设备默认无读写权限，
sudo chmod 666 /dev/arm*
才能打开；② 校准文件按 robot id 命名存放，双臂要复制成 bimanual 左/右四份；③ 视频用 SVT-AV1 编码落盘，
Map: 100%
期间不能碰机械臂。三条合起来，正好解释课段 1 那两个故障。
图 1-1｜单臂遥操作工位实景：操作员手持主臂（leader）发出 60 Hz 关节指令，从臂（follower）在桌面实时跟随执行，腕部摄像头与显示器构成视觉反馈闭环（第 06 章）

  --robot.id=left_follower_arm \

注意虚线回路：采集是"一条做完、复位、再做下一条"的循环，复位期保证每条 episode 从相同初始状态出发——这直接决定 EXP-02 训练时数据分布是否干净。
看动画时对照两条实线：紫色实线是串口指令流（人 → 从臂，60 Hz），绿色实线是视觉流（摄像头 → 数据集，30 fps）——两条流在同一时间轴上对齐落盘，才构成"图像 + 状态 + 动作"三元组。

08
常见问题
课段 8 · 融会贯通 · 13 min
✓
串口打不开
：先
sudo chmod 666 /dev/arm*
；设备号变了就
ls /dev/arm*
重查。
✓
双臂一动不动
：多半没复制 4 份校准文件，或启动后没按回车；启动提示 Mismatch 时按 ENTER 使用已有校准文件。
✓
显示 Mismatch between calibration values…
：直接 ENTER（沿用 id 对应文件）；只有想重刷电机才输入
c
。
✓
退出时报 gRPC ERROR / winit DISPLAY / FATAL: exception not rethrown
：清理期的正常噪音，确认已打印 Exiting 即可。
✓
数据集是空的
：检查
dataset.repo_id
命名、是否录入超过 episode_time_s 的时长，以及缓存目录
~/.cache/huggingface/lerobot/<名>/<集>/
。
✓
摄像头 index 被占用
：画面黑屏或启动报无法打开设备时，用
ls /dev/video*
核对，并关掉其他占用该 index 的预览程序（含上次未退净的采集终端）。
