02
核心原理：云训练 ↔ 真机推理的闭环
课段 1 收尾 + 课段 2 · 激活旧知 · 8 min
❓ 聚焦问题（课段 1）
学员上云最常踩的三个坑：
本地 GPU 跑一夜还没训完 5000 步
，
云实例忘关机被扣了一整晚费用
，或者
推理命令跑完机器人一动不动
——明明检查点下载回来了，从臂却像没收到指令。问题出在哪？带着这三个故障听完全课，到课段 6 你会亲手让机器人自主抓起红方块。
通俗类比
：这就像"厨师在中央厨房练手艺（云端 GPU），学成后回到家里做饭（本地机械臂）"。训练吃算力（几小时到几天的矩阵乘法），推理吃实时性（60 Hz 内必须吐出动作）。两者天然分离，所以工程上分工：云上练模型、本地跑部署。
训练侧
：LeRobot 镜像把 CUDA、PyTorch、LeRobot 依赖预装好，一条
pip install -e .
即完成源码安装。数据靠 zip 上传，训练产出的
checkpoints/last/pretrained_model
是一个自包含目录（config + 权重 + 处理器），下载回本地即可用。
推理侧
：推理复用了采集命令
lerobot-record
，但
去掉了 --teleop
，改为加
--policy.path=/…/checkpoints/last/pretrained_model
。此时每个控制周期的数据流变成：三摄像头图像 + 6 维状态 → 喂给策略 → 得到 100 步动作块 → 取前 n 步下发给关节 → 下一周期再推理。日志里
'policy': {input_features: observation.images.left/side (3,480,640), observation.state (6,), output_features action (6,)}
就是这份"策略契约"。
episode_time_s=60
让机器人有一分钟自主发挥。
为什么 repo_id 加 eval_ 前缀
：推理也要开启 recorder 记录表现（方便回看与评估），但这些数据不是训练原料，用
eval_
命名和训练集彻底分开，避免后来者把"机器人的尝试"误当成"人类示范"混进训练。
↺ 激活旧知（课段 2）
回忆前两个实验两条旧知：① EXP-01 采集用
lerobot-record --teleop …
，动作来源是
人掰主臂
；② EXP-02 训练产出
checkpoints/last/pretrained_model
自包含目录（config + 权重 + processor）。推理就是把
--teleop
换成
--policy.path
——动作来源从"人"变成"模型"，命令几乎没变。
云端部署
JupyterLab 新终端执行
cd /data/lerobot/
+
pip install -e .
，安装完成后终端无报错返回提示符，即可进入训练流程（第 11 章）。
推理契约
推理启动日志打印
'policy': {input_features: observation.images.left/side (3,480,640), observation.state (6,), output_features action (6,)}
——这正是策略的输入输出契约：三路图像 + 6 维状态进、6 维动作出（第 12 章）。
对照记忆
采集 = record + teleop；推理 = record + policy.path。
同一个命令，换掉"谁来给动作"。

08
常见问题
课段 8 · 融会贯通 · 13 min
✓
推理时显存不足
：确认图片分辨率参数与训练一致（(3,480,640)），关掉 --display_data 的高负载预览，减小 batch 类参数。
✓
找不到 policy.path
：路径必须精确到
checkpoints/last/pretrained_model
目录本身（不是 checkpoints），内含 config 与权重。
✓
启动报 Mismatch…Press ENTER
：直接 ENTER 沿用现有校准文件。
✓
机器人一动不动
：检查 policy.path 是否加载成功（看 Loading weights 日志）、任务初始摆位是否与训练一致、episode_time_s 是否太短。
✓
云端 pip 慢 / JupyterLab 传大文件断
：换国内源、分卷上传 zip 或改用 scp/rsync。
✓
忘记关机被扣费
：下机前固定动作——控制台 → 实例 → 关机；课程结束 → 更多 → 释放实例（复制 ID 前五位确认）。
✓
检查点拷到推理机后加载失败
：
pretrained_model
必须整目录传输（config.json、权重、processor 缺一不可），打包压缩时保留目录层级。
