02
原理：帧-动作对与 ACT 学习
课段 1 收尾 + 课段 2 · 激活旧知 · 8 min
❓ 聚焦问题（课段 1）
采集了 200 组数据，训练却报"找不到 robot_data.csv"——一查发现某个编号目录里 CSV 缺列、目录名不是纯数字。问题出在哪？带着这个故障听完全课——到课段 5 你会亲手跑通转换。
转换这一步在干「对表」：采集时存下的是三路视频和一堆关节角 CSV，训练框架要的是
每一帧画面配同一时刻的动作
——第 t 帧图像 ↔ 第 t 拍关节角，帧帧对齐后写成 parquet + mp4 + meta 三件套，这就是 LeRobot v3.0 数据集。训练则是让 ACT 网络做题：
输入画面（和历史动作块），输出接下来一串动作
；对答案（loss）越对越准，权重就存成 checkpoint。
对齐粒度
视频帧率与 CSV 采样必须对得上（家庭案例 30fps），错位即全废。
ACT 特点
Action Chunking：一次预测一串后续动作，再分拍执行，动作更平滑不抖。
loss 怎么看
总体下降即在学；突然爆麦多半是 OOM 或学习率过大，回参数表排查。
checkpoint
按 save_freq 周期落盘，推理只认最终可用的那个目录（EXP-04 会用）。
↺ 激活旧知（课段 2）
回忆看外语片配字幕：字幕和画面错位就看不懂。转换干的就是"重新对齐"——第 t 帧画面配第 t 拍动作，帧帧对齐写成 v3.0 数据集；训练则是让 ACT 反复"听写"这盘带子，直到能不看字幕跟读。
生活化类比：
转换好比把「错位的字幕和视频」重新压制成强制对齐的版本——画面播到哪句，字幕正好是哪句；训练则是让学员听写这盘带子几十遍，直到能不看字幕跟读。

06
源码解析：convert_lerobot_v3_fixed_simple.py
示证新知 · 读代码
转换不是魔法，理解它最好直接读转换脚本。本实验用的
convert_lerobot_v3_fixed_simple.py
是一个标准
四阶段流水线
：
读 CSV → 并 parquet → 并视频 → 写元数据
。下面先把最关键的
CSV 读取函数
逐行拆开看，它藏着本实验最容易踩的坑。
# ---- 读取单个 episode：robot_data.csv ─────────────────────────────
# ⚠️ CSV 格式坑：原始表头 33 个列名，但数据行末尾多一个逗号（共 34 列）
#    pandas 默认 read_csv 会把第一列 timestamp 当成 index，
#    导致 l_a_0..r_s_7 全部循环左移 1 位（df['l_a_0'] 拿到的是原始 l_a_1）。
#    这里治本：显式给出 34 列名（含末尾哑列 '_trailing'），并 skiprows=1。
def read_episode_data(self, episode_dir):
    csv_path = episode_dir / "robot_data.csv"
# 34 个字段：timestamp + l_a_0..7 + r_a_0..7 + l_s_0..7 + r_s_0..7 + 末尾空列
col_names = (['timestamp']
                 + [f'l_a_{i}' for i in range(8)] + [f'r_a_{i}' for i in range(8)]
                 + [f'l_s_{i}' for i in range(8)] + [f'r_s_{i}' for i in range(8)]
                 + ['_trailing'])
# skiprows=1 跳过原始 header；header=None + 显式列名，终结列偏移
df = pd.read_csv(csv_path, header=None, names=col_names, skiprows=1, index_col=False)
    df = df.drop(columns=['_trailing'])
# 末尾哑列丢弃
# action = 主动臂命令（8 左 + 8 右 = 16 维）
action_cols = [f'l_a_{i}' for i in range(8)] + [f'r_a_{i}' for i in range(8)]
    action = df[action_cols].values.astype(np.float32)
# state  = 从臂状态（用 0 填充 NaN，主要 r_s_7 硬件无反馈）
state_cols = [f'l_s_{i}' for i in range(8)] + [f'r_s_{i}' for i in range(8)]
    state = np.nan_to_num(df[state_cols].values.astype(np.float32), nan=0.0)
    return action, state, len(df)
🔑 这段代码解释了上文的"33 列 / 34 列"
表头只有 33 个名，数据行却 34 个字段——就是末尾那个多出来的逗号。
pandas 默认读会把 timestamp 当索引→所有列整体左移 1 位。
所以脚本才用
skiprows=1 + 显式 34 列名 + '_trailing' 占位
来对齐。你能看出，若不这样修，
action
的 l_a_0 实际拿到的是什么吗？（答案是 l_a_1。）
阶段 1/4
读所有 episode 的 CSV，抽出 action(主臂) 与 state(从臂)，用 tqdm 显示进度。
阶段 2/4
把所有帧 concat 成一个 PyArrow 表，写
data/chunk-000/file-000.parquet
。
阶段 3/4
三路相机分别用
ffmpeg concat
合并为 H.264 mp4 存入 videos/。
阶段 4/4
生成 meta 三件套：info.json / tasks.parquet / stats.json + episodes 元数据。
其中
阶段 4 最关键
：
info.json
声明
特征结构
（action/state 都是 16 维 float32、三路图 shape=720×1280×3），
tasks.parquet
把任务文本（如 "place fruits in the box"）当作 task 索引，
stats.json
提供每维 min/max/mean/std——这些
训练侧
make_dataset
启动时读取校验
。假如 stats.json 缺了
observation.images.*
三路图像统计，且开了
use_imagenet_stats=True
，训练会直接 KeyError——这就是为什么脚本里用
VISUAL: IDENTITY
占位。
思考
若把脚本
fps=30
改小到 10，你认为会影响
info.json
里的哪个字段？又会让视频「看起来」变快还是变慢？（提示：影响的是元数据声明 fps，还是实际视频流帧率？）
06
动画：帧-动作对的对齐与成批
课段 4 · 示证新知 · 12 min
视频画面（三路）
同拍关节动作（CSV 行）
v3.0 数据集
parquet + 三路 mp4
meta/info·tasks·stats
光标扫到哪一拍，就把「这一帧画面」和「这一拍动作」配成一对写进数据集
动画：扫描框逐拍对齐上下两条轨道（画面帧 ↔ CSV 动作行），配好的对子沿轨道汇入右侧 v3.0 数据集容器——帧与动作错一格都不行。
观察
如果视频是 30fps、CSV 却按 50Hz 存，两条轨道的「拍数」对不上——这就是转换脚本要按帧率重采样对齐的原因；对不齐时宁可重转，也别让模型学错位映射。

08
常见问题
课段 8 · 融会贯通 · 13 min
Q 转换报「找不到 robot_data.csv」？
检查编号目录里是否完整，CSV 表头需 33 列、数据行 34 列的契约（02 文档）。
Q 转换报视频/FFmpeg 错？
ffmpeg -version 先验证；Pillow 未装会用默认值导致失败——依赖表逐项补齐。
Q 训练 loss 不降？
