02
原理：从散装记录到「帧-动作对」教材
课段 1 收尾 + 课段 2 · 激活旧知 · 8 min
❓ 聚焦问题（课段 1）
学员最常翻的车：训练跑了半天 loss 死活不降，甚至直接 KeyError——回头查才发现 episode 163 是坏组没跳过、CSV 的 _trailing 哑列没修、帧和动作错位了半拍。问题出在数据转换，不在模型。带着这个痛点学完整课——到课段 6 你会亲手把散装记录炼成一份干净教材。
原始采集是一堆按编号存放的文件夹：CSV 关节角 + 零散视频帧，格式是自定义 33 列表头/34 列数据。转换器把它们
像装订相册一样
：每组 episode 的每一帧配一条动作标签，照片按时间码贴齐，最后压成标准 Parquet + MP4 + meta 清单。训练时 ACT 每次抽一个 batch，看「这一帧画面 + 当前 16 维关节状态」，预测接下来 100 步动作块（chunk_size=100），预测与人的示范做差——这个差回传（kl_weight=10、use_vae=true），网络就一点点「越看越像你」。
阶段1 读取
read_episode_data 解析 34 列 CSV（修复 _trailing 哑列、r_s_7 的 NaN→0），取出 16 关节真值。
阶段2 Parquet
[Nᵢ,16] 各文件 concatenate 成 [ΣNᵢ,16]，加 7 元数据列写入 data/chunk-000/file-000.parquet。
阶段3 视频
ffmpeg concat demuxer 以 -c copy 流复制拼接三路相机视频，不重编码、不掉帧、不耗 CPU。
阶段4 meta
info.json（features dtype/shape）+ tasks.parquet（任务名即标签）+ stats.json + episodes 统计。
↺ 激活旧知（课段 2）
回忆两件旧事：① 装订相册——把散装照片按「一次完整活动」分组、按拍摄时间排好、写上拍摄说明，才能当教材用；② 学徒背书——翻得越勤记得越牢，但教材装订错了（页码错位），背得越勤奋错得越狠——所以转换就是装订教材，训练就是背书，数据质量 > 数据数量。
阶段1 数据流：
Episode 180–209 的
[Nᵢ,16]
关节矩阵逐个 concatenate 成
[ΣNᵢ,16]
；阶段2 再补 7 元数据列（episode_index / frame_index / task 等）转成 Parquet。
生活化类比：
转换 = 把手机相册（散图）按「一次完整分拣」分组、按拍摄时间排好、写上拍摄说明（meta），炼成一本训练教材；训练 = 学徒反复翻这本教材，把你的手法记进肌肉记忆。
教材装订错了（帧动作错位），学徒学得越勤奋错得越狠——数据质量 > 数据数量。

关键命令
随课段 5 / 6 对照使用
# ① 环境（03-数据训练：Python 必须 3.10）
conda create -n lerobot python=3.10 -y
conda activate lerobot && conda install ffmpeg -y
git clone <lerobot仓库> && cd lerobot && pip install -e .
# ② 转换的四种切法（02-数据转换 / 工厂场景案例）
python convert_lerobot_v3_fixed_simple.py --input ... --output ... \
  --start 180 --end 209
# 场景1：连续区间
python convert_lerobot_v3_fixed_simple.py ... --skip 163,172,202
# 场景2：剔坏组
python convert_lerobot_v3_fixed_simple.py ... --task
"Parts Categorization"
# 场景3：任务名
# ③ 训练（工厂场景案例真实命令）
lerobot-train \
  --policy.type=act \
  --dataset.repo_id=lindenbot/parts_categorization \
  --dataset.root=/home/lindenbot/converted_data \
  --output_dir=~/lerobot-0.4.1/output/act_fac \
  --job_name=
"place fruits in the box"
\
  --batch_size=12 --steps=50000 --save_freq=4000 \
  --log_freq=100 --num_workers=8 \
  --wandb.enable=false --policy.push_to_hub=false --policy.use_amp=true
参数速记：
batch_size=12（显存不够就降）· steps=50000（示例步数；案例复盘建议 500000 步以上更稳）· save_freq=4000（每 4000 步存档）· use_amp=true（AMP 混合精度省显存）。

课段 7 · 应用新知 · 10 min
Q1：4060 Ti 上训练报 CUDA OOM，第一优先级调什么？
A. 把 steps 从 50000 加到 500000
B. 降低 batch_size（12 → 8 → 4）
C. 删掉视频目录省磁盘
Q2：转换日志说「跳过 episode 163」，该怎么办？
A. 报错中断，必须补齐 163
B. 属正常——163 是被 skip 的坏组，跳过即预期
C. 改用 --start 163 --end 163 重转
重置答题
已答 0 / 2
超参直觉：
batch_size 管显存、steps 管时长、save_freq 管后悔药、log_freq 管心跳
。数据量大而步数少 = 没看完书；步数多而数据烂 = 背错书。
08
常见问题
课段 8 · 融会贯通 · 13 min
Q torch.cuda 为 False？
PyTorch 装成 CPU 版了：按 03-文档重装对应 cu121/cu118 轮子，nvidia-smi 先确认驱动。
Q pip install -e . 超慢/失败？
用文档给出的镜像加速方案（清华源/代理），补装 opencv-python-headless、libGL、evdev 等缺失依赖。
Q 找不到数据集？
确认 --dataset.root 指向 converted_data 且 data/videos/meta 三目录齐全；路径写错会直接 FileNotFoundError。
Q loss 不降？
先查数据：帧动作是否错位、任务名是否唯一、坏组是否混入；再查 lr/batch——多数是数据问题不是模型问题。
产物打包（云端路线）：
训练产出按 save_freq 落 checkpoint 目录（如
outputs/sort/ACT/checkpoints/050000/pretrained_model
），zip 上传至
/root/gpufree-data
供真机推理取用。
视频阶段前置检查：
ffmpeg -version
确认可用；concat demuxer 负责三路相机视频的无损拼接（
-c copy
流复制，不重编码、不掉帧、不耗 CPU）。
