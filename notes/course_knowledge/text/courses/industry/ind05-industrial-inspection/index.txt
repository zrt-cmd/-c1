核心理念：
移动机器人巡检的本质是「先认识地方，再知道自己在哪，然后按路线办事」。四足只是腿，
SLAM 给它地图、AMCL 给它位置、Nav2 给它路线、YOLO 给它眼睛
——四样凑齐，机器狗才从遥控玩具变成巡检员工。
STRUCTURE
课程结构
四步能力阶梯：会动 → 会画 → 会走 → 会看
SDK 运动控制
安装 Unitree SDK 与 ROS2 Go2 驱动，速度指令遥控前进转向、站立趴下、读取状态，打牢巡检的「腿」。
3D 激光建图
启动 3D 激光与 slam_toolbox 建图节点，遥控遍历场地，生成 3D 点云与 2D 栅格地图并保存，得到巡检的「地图」。
定位与多点导航
配置 AMCL 初始位姿与 Nav2 参数，编排多个巡检点，让 Go2 依序自主到达并避障——巡检的「路线」。
视觉闭环与报告
巡检点拍照，YOLOv8/ONNX 识别表计读数或异常目标，汇总生成巡检日报并自主回充——巡检的「眼睛和交付」。

CLASS
课堂组织建议
面向真机 + 机房双场景教学
分组：
2 人 1 组对标真机作业的「操作手 + 安全员」——一人发指令、一人盯狗避障，角色每轮互换。
场地固定：
巡检场地用胶带标出充电桩 dock 矩形，桌椅陈设中途不挪动，换组时按照片复原。
低速铁律：
所有速度指令从最低档起步，机器人抬腿异常立即趴下断控，避免跌落与碰撞。
地图版本：
每组地图按「组号-日期」命名，Save Map 与 Serialize Map 双落盘，当天归档不留口头。
演示前置：
每实验开场 10 分钟回放上一实验录像或闭环演示，保持「先看再做」动线。
验收关口：
EXP-01 查运动、EXP-02 查地图、EXP-03 查依序到达、EXP-04 查报告与回充，四关不过不进下一实验。
安全底线：机器狗运动范围内不站人，任何异常先发 Stop/趴下指令再排查；狭窄与临边区域禁入，回充桩周围保持净空。

PIPELINE
巡检闭环数据流
每一环的输出是下一环的输入契约
S1 · 建图
点云 → 栅格地图
3D 激光 utlidar/cloud 经 slam_toolbox 融合成 /map，Save 出 yaml+pgm、Serialize 出 posegraph。
S2 · 定位
地图 + 传感器 → 位姿
AMCL 一簇粒子不断淘汰修正，输出 odom→map 短正，初始位姿用 2D Pose Estimate 给定。
S3 · 导航
位姿 + 巡检点 → 速度
Nav2 全局规划 + 局部避障，waypoint_follower 按序下发目标，每点到达等收敛再走。
S4 · 识别与报告
图像 → 检测 → 日报
巡检点触发拍照，YOLOv8/ONNX 输出框+置信度，脚本汇总成巡检日报并规划回充。

FAQ 1
没有真机也能学吗？
能。本课全部基于开源栈，无真机时用 setup_local.sh 回环接口与仿真/录包完成大部分流程。
FAQ 2
为什么要先建图再导航？
AMCL 定位的本质是「拿当前观测去已知地图里比对」，没有地图就没有可比对的参照物。
FAQ 3
Gazebo 里四足能走吗？
unitree_ros 的 go2_description 在 Gazebo 只支持底层关节仿真、不支持完整行走——这是明确局限，课上讲清。
FAQ 4
检测漏检误检怎么办？
两头治理：光照不足先补光，再标定 confidence 阈值——阈值调低多检也多误，调高少误也漏检。
