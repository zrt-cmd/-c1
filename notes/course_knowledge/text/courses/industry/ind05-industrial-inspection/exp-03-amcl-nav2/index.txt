02
原理：SLAM / 定位 / 导航（理论 2 融合）
课段 1 收尾 + 课段 2 · 激活旧知 · 8 min
❓ 聚焦问题（课段 1）
学员现场最常遇到的怪事：
巡检点明明标在表计前，狗却停在两米外拍照
；
/amcl_pose
协方差一直很大，粒子满图飞。问题出在哪？带着这个故障听完全课——到课段 6 你会亲手让狗精准到位。
三个角色一台戏：
EXP-02 画好的地图是
「城市地图」
；AMCL 是
「我在地图的哪」的猜谜游戏
；Nav2 是
「高德导航」
——知道地图加知道位置，它负责规划绕障路线并把油门方向盘发给四足。缺任何一个，狗都不是巡检员，只是随机遛弯。
AMCL：一群猜测不断淘汰
AMCL（自适应蒙特卡洛定位）的玩法：
撒一把纸屑
——在地图各处随机撒 2000 个「我可能在这」的粒子；每个粒子都拿当前激光扫描与地图比对，「如果我真在这，看到的景象对得上吗」，对得上的留下并繁殖，对不上的直接淘汰；几轮之后，所有粒子挤成一团，那团中心就是你的位置。
初始一无所知时粒子满图乱飞，一旦你说「我其实在充电桩旁边」（2D Pose Estimate 给初值），粒子团会唰地收敛
——这就是「定位收敛」的直观含义，也是「每点需收敛后再出发」的科学依据：粒子还没抱团就发车，狗会拿着错误位置自信地撞墙。
Nav2：高德地图导航的机器人版
Nav2 收到目标点后干三件事：
①全局规划
（在栅格地图上画出理论最优路线）→
②局部控制
（controller 按周期算每一步往哪迈，go2_ros2_sdk 参数里 controller_frequency 为 3.0Hz，匹配四足步态节奏）→
③实时避障
（代价地图里突然出现人/纸箱，局部规划当场绕开）。四足 Go2 可横移平移，所以用
nav2_amcl::OmniMotionModel
（全向运动模型）比差速小车模型更贴合；多点巡检则交给
nav2_waypoint_follower
——「把这串点按顺序走完，每到一个可以停一停」。
一句话版本：
SLAM=画地图；AMCL=地图上自拍定位（一群猜测不断淘汰）；Nav2=高德地图导航（规划+避障+踩油门）；waypoint_follower=批量下单「一口气巡完 N 个点」。

载图：
把 map.yaml / map.pgm 放到导航参数指定路径，启动
ros2 launch go2_robot_sdk robot.launch.py
（内置 slam_toolbox、Nav2、RViz），并
停掉建图节点
——建图与定位不要同时发 map，静态地图由 map_server 独家供图。
给初值：
RViz 点
2D Pose Estimate
，在地图上从充电桩位置拖出方向箭头——箭头起点放狗的真实站位、朝向拖准；AMCL 粒子应从满图散点唰地抱团。
判定收敛（技巧）：
让狗小幅前后挪 0.2m——激光轮廓与地图墙体
贴合不重影
、粒子团紧致，才算收敛；没收敛就再给一次初值。
编排路线：
用 RViz
Waypoint / Nav Through Points
工具在地图上依次落点 P1~Pn；或直接调用 follow_waypoints 服务把姿态数组一次下发。
依序执行：
狗自主逐点到达；每到一点等待定位收敛（粒子不发散、朝向稳定）再执行下一点；途中人为放纸箱，验证局部避障绕行。
留痕：
记录每个点的到达时刻与偏差，任何一点「冲过头/到错位」都回查 AMCL 粒子状态与 /amcl_pose 协方差。
验收闸门：
全部巡检点按投放顺序到达且无撞障；抽查任意一点停稳后激光与墙体贴合——顺序错、到点偏、粒子发散三者出现其一即不通过。

关键命令
随课段 5 / 6 对照使用
AMCL 参数与 waypoint_follower 来自 Nav2 官方文档；launch 与参数路径沿用 go2_ros2_sdk。
# ① 启动（内置 map + AMCL + Nav2 + RViz；建图节点需按步骤停掉）
export ROBOT_IP=192.168.123.161
export CONN_TYPE=cyclonedds
ros2 launch go2_robot_sdk robot.launch.py
# ② RViz 操作（鼠标）：2D Pose Estimate 给初值 → 等粒子抱团
#    nav2_params.yaml 关键片段（沿 Nav2 官方结构）：
#    amcl: robot_model_type: "nav2_amcl::OmniMotionModel"  # 四足全向
#          max_particles: 2000   laser_model_type: "likelihood_field"
#    controller_server: controller_frequency: 3.0           # 3Hz 控制循环
# ③ 多点巡检：一次下发巡检点队列（nav2_waypoint_follower 服务）
ros2 service call /follow_waypoints nav2_msgs/srv/FollowWaypoints \
  "{poses: [{header: {frame_id: map}, pose: {position: {x: 2.1, y: 0.6}, orientation: {w: 1.0}}},
            {header: {frame_id: map}, pose: {position: {x: 4.0, y: 2.5}, orientation: {w: 1.0}}}]}"
#    也可以不用命令行：RViz 顶部 Waypoint 工具逐点投放，效果相同
# ④ 监控定位质量（收敛判据看这两个）
ros2 topic echo /amcl_pose --once
# 协方差椭圆应越缩越小
ros2 topic echo /particle_cloud --once
# 粒子云：抱团=收敛，满图飞=未收敛
观察
每到一个巡检点，
/amcl_pose
的协方差会先涨（起步扰动）再降；
看到协方差回落、粒子抱团再发车
，就是「定位收敛后再出发」在数据上的样子。
规划谁说了算
PlannerServer 全局画线；ControllerServer 局部 3Hz 跟线；两层解耦，绕障不推翻全局路线。
代价地图两层
static 层放 EXP-02 地图，obstacle 层实时吃激光——人走过来会被实时标记为膨胀障碍。
为啥用 Omni 模型
四足可原地横移，差速模型会把横向漂移当误差猛纠，Omni 则视为正常运动。
到点判定
goal checker 按位置/朝向容差判定「到达」；容差太紧反复踱步，太松拍照对不准。

+ P1 表计位 (2.1, 0.6)

08
常见问题
课段 8 · 融会贯通 · 13 min
Q 初始位姿给了还是飞？
箭头方向拖反、或给位姿时狗其实在别处：把箭头起点放在狗真实站位、朝向拖准；仍散则小幅挪动让观测刷新。
Q 走着走着定位漂了？
长直走廊特征少（对称墙迷惑观测）：补桌面/柱子等非对称特征，或在该段降速多留观测帧。
Q 到点总差半米？
goal checker 容差与地图分辨率不匹配：先核对 map.yaml 的 resolution/origin，再微调 xy 容差。
Q follow_waypoints 报 404？
waypoint_follower 节点没起：确认 launch 拉起了 navigation_launch 全套，ros2 node list 里能看到它。
Q 遇人就停不绕？
obstacle 层没吃到激光或膨胀半径过大：检查 pointcloud_to_laserscan 输出与 obstacle 层 topic，膨胀调回合理值。
Q 电机哼哼/原地踱步？
定位抖动导致 controller 反复纠偏：等收敛、减小目标抖动；确认用 Omni 模型而非差速模型。
Q 建图节点要关吗？
要：建图与 AMCL 同时发 map 会互相覆盖，静态地图必须由 map_server 独家供图。
Q 能中途加点吗？
可以向队列继续发 follow_waypoints 请求；但每批点都遵守「到点—收敛—再出发」节奏，别连珠炮。
