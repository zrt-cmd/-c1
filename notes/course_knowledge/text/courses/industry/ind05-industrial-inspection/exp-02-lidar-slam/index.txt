02
原理：3D 点云建图（SLAM）讲透
课段 1 收尾 + 课段 2 · 激活旧知 · 8 min
❓ 聚焦问题（课段 1）
学员现场最常遇到的怪事：
绕场一圈存了图，重载发现同一面墙画出两条线
，起点和终点错开半米——这就是"漂移"。问题出在哪？带着这个故障听完全课——到课段 6 你会亲手用回环把它拉直。
把建图想象成「蒙眼画房间」：
你被蒙着眼在房间里走，手里的一根激光笔每毫秒向四周量一次距离——右手边 2.3 米有面墙、正前方 4.1 米是柜子……把这些「距离点」按你的走位反投影到空间里，点越攒越多，房间的轮廓就浮现了。这就是
3D 点云建图
。难点有两个：一是
你不知道自己走到哪
（得边走边定位，即 SLAM = Simultaneous Localization And Mapping，同步定位与建图）；二是
每一步的定位误差会累加
，走一圈回来发现「起点和终点对不上」——这就是漂移。
Go2 上的三级流水线
① 传感器出点云
3D 激光雷达（Mid-360 / XT16 级多线激光）旋转扫描，发布 utlidar/cloud（sensor_msgs/PointCloud2，frame_id=utlidar_lidar）。
② 3D 压成 2D
pointcloud_to_laserscan 把点云裁剪压平成一束「虚拟单线激光」——因为巡检地图按楼层平面画就够用，算力省一个量级。
③ SLAM 拼图
slam_toolbox online_async 拿激光束做scan匹配：找最优位姿把新扫描「贴」进地图，同时输出自己在哪。
④ 出两种图
Save Map 出 map.yaml + map.pgm（给 Nav2/AMCL 用的 2D 栅格）；Serialize Map 出序列化点云图（供 slam_toolbox 二次精修）。
回环：让地图「拉链对齿」的唯一办法
scan 匹配每一步都有一点点误差，走 100 米可能错出半米——地图里的墙会「重影」。但若你
绕场一圈回到起点
，建图算法会认出「这面墙我见过！」（回环检测），把首尾强行对齐并把误差摊销到整条轨迹上，墙立刻变直。这就是培训方案强调的技巧：
闭合回路提升建图质量
。
生活化类比：
slam_toolbox 像「接力描图纸」：每次扫描是一张半透明硫酸纸，按最佳角度叠上去；回环就是把第一张和最后一张用夹子对齐——中间所有纸的错位一起被修正。
↺ 激活旧知（课段 2）
回忆三条旧知：①
坐标系与 TF
（EXP-01 已通链路，雷达有 frame_id）；②
激光测距原理
（每束激光返回一个距离值，攒成点云）；③
累积误差
（每步小错累加成大错）。三条合起来，正好解释课段 1 那个故障。
图 2-1｜Go2 实时 3D 点云建图效果（来自 abizovnuralem/go2_ros2_sdk 仓库 README 演示动图）：随着机器人移动，房间点云被逐帧拼接成完整轮廓——本实验要复现的正是这个过程。

为啥压成 2D
巡检按平面路网走位，2D 栅格足够 AMCL/Nav2 用，内存与算力都降一个量级。
为啥是 online_async
建图放后台线程跑，前台遥控不卡顿——实时性与质量的折中。
地图存哪
Save Map 产 map.yaml(metdata+分辨率)+map.pgm(灰度像素)；Serialize 存 slam_toolbox 内部结构供再编辑。
下次实验怎么用
EXP-03 的 AMCL 直接吃 map.yaml；序列化图留给想修改地图结构的同学。

动画：点云逐帧建图与回环
课段 4 · 示证新知 · 12 min
逐帧累积：点越攒越多
黄块=Go2　绿点=逐帧写入的点云　虚线=探索轨迹（绕场一周）

起点 ≠ 终点，错位 ≈ 每步误差 × 步数

08
常见问题
课段 8 · 融会贯通 · 13 min
Q RViz 里没有点云？
先 echo --no-arr /utlidar/cloud 查 frame_id，再把 Fixed Frame 改成该 frame；话题没数据则回 EXP-01 查 DDS 链路。
Q 点云「拉花」重影？
走太快或机身晃动过大：降低速度、保持匀速直线；地面打滑时等步态稳定再走。
Q 启动 launch 报找不到包？
没 source go2_ros2_sdk 工作空间：source install/setup.bash 后重开；确认 CONN_TYPE 与网线/WiFi 匹配（cyclonedds | webrtc）。
Q 地图墙体错位重影？
回环没闭合或闭合时匹配失败：沿特征丰富的墙体重走一圈，起点终点重叠 2~3 米再存图。
Q Save / Serialize 都要吗？
Save 产 2D 栅格（AMCL 必需）；Serialize 产可再编辑的序列化工件——验收两个都要交。
Q 空旷走廊建不了图？
特征太少 scan 匹配无从下手：临时摆放纸箱/锥桶造特征，或沿有货架、柱子的一侧行走。
Q launch 太重卡顿？
该 launch 默认连 Nav2/RViz/Foxglove 全开：先只留建图调通，再逐步打开其余节点。
Q 地图坐标和充电桩对不上？
务必用 Start At Dock 定原点；后期随手重启建图会让位姿原点漂移，EXP-04 回充就找不到桩。

slam_toolbox 调参
：loop_search_minimum_linear_distance（回环搜索距离）、ceres 线性求解器参数——地图重影时的第二把钥匙。

：go2_ros2_sdk 同时发布点云与 TF，配合 Foxglove 可回放建图全程，交作业时附回放比截图更有说服力。
3D→2D 的取舍
：多层建筑需要分层建图；本课场景（单层厂区）以栅格为主，3D 点云留存作碰撞与货架核查的底档。

思考 1
为什么把 3D 点云压成 2D 栅格是「划算」的？举一个 2D 栅格
不够用
的巡检场景（提示：想想立体障碍物），并说明补救思路。
