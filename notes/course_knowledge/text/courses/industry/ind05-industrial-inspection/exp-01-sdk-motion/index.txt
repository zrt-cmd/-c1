02
原理：四足运动与巡检概述（理论 1 融合）
课段 1 收尾 + 课段 2 · 激活旧知 · 8 min
❓ 聚焦问题（课段 1）
学员现场最常遇到的怪事：
SDK 脚本跑完，狗纹丝不动
；
ros2 topic list
是空的，机器狗仿佛"失联"。问题出在哪？带着这个故障听完全课——到课段 6 你会亲手让它动起来。
把机器狗想像成一位厂区巡检员：
四条腿是它的「交通工具」，身上的雷达和相机是「眼睛」，脑子是机载的 Jetson Orin。它要干的活就三样——
抄表
（对着表计拍一张，后面用 YOLO 认数字）、
看异常
（跑冒滴漏、烟火、异物）、
自己巡逻自己充电
（定时出门，见桩就回）。这三样任务的共同前提：
狗得先听指挥、走得起、停得稳
——这就是本实验要打通的运动控制层。

四足运动能力：一个运动服务管所有动作
Go2 的运动不靠你直接拧电机——机上跑着一个
运动服务（sport mode）
，你发「请求」，它负责步态平衡。订阅
/sportmodestate
话题能看到它的状态字典，其中两个字段最常读：
mode
（0=默认站立、1=平衡站立、3= locomotion 运动中、5=趴下、8=恢复站立……）与
gait_type
（0=待机、1=trot 对角小跑、2=run、3=爬楼），外加 body_height、velocity、foot_force 等。控制侧走
/api/sport/request
话题发
unitree_api/msg/Request
请求——SDK 里的站立/趴下、速度移动、姿态控制，底层都是它。
站立 / 趴下
SDK 的 StandUpDown()：起身与卧倒，是每轮实验的第一与最后一个动作。
速度指令
VelocityMove()：vx/vy/yaw 三元组遥控——前进、平移、原地转向都从这里来。
姿态指令
BalanceAttitude()：调整机身 roll/pitch/yaw，过坎抬身用得上。
状态回读
read_highstate / /sportmodestead：发完指令必须回读，确认狗真的动了。

配网：
网线连接 Go2，网卡 IPv4 设静态（示例 192.168.123.99/24），
ifconfig
记下接口名。
装 Python SDK：
依赖 Python≥3.8、cyclonedds==0.10.2、numpy、opencv-python；源码方式
pip3 install -e .
（找不到 cyclonedds 时先本地编译并导出 CYCLONEDDS_HOME）。
装 ROS2 驱动：
克隆 unitree_ros2 → 安装 rmw_cyclonedds 依赖 → 编译 cyclonedds_ws 与 unitree_go/unitree_api 包 → 用 setup.sh 配置接口名与 RMW_IMPLEMENTATION。
验证链路：
ros2 topic echo /sportmodestate
有数据滚动即通；无真机时用
setup_local.sh
（回环口 lo）跑本地流程。
运动序列：
先 StandUpDown 站起 → VelocityMove 用最低速度档走直线与小半径转向 → 收到停止 → 趴下 → 回读状态确认 mode/gait 正常。
留痕：
录下「指令-动作」对照视频或截图状态话题，作为「指令驱动四足运动正常」的验收证据。
图 1-3｜
ros2 topic echo /sportmodestate
实测输出（来自 unitreerobotics/unitree_ros2 仓库 README）：position、velocity、yaw_speed、gait、foot_force 随运动实时刷新——这就是验收时要看的「心跳」。
图 1-4｜预检激光通道：
ros2 topic echo --no-arr /utlidar/cloud
查到 frame_id 为 utlidar_lidar（来自 unitree_ros2 仓库 README）——EXP-02 建图就靠这条话题。
图 1-5｜指令下发后四足关节实时同步效果（来自 abizovnuralem/go2_ros2_sdk 仓库 README 演示动图）：URDF 模型随真机关节 1:1 动，说明运动链路全通。
05
关键命令
随课段 5 / 6 对照使用
以下命令均摘自 unitree_sdk2py 与 unitree_ros2 官方 README，网卡名按实机替换。
# ① 安装 Python SDK（依赖 cyclonedds==0.10.2 / numpy / opencv-python）
git clone https://github.com/unitreerobotics/unitree_sdk2py.git
cd unitree_sdk2py && pip3 install -e .
# ② 读高层状态（enp2s0 换成连接机器狗的网卡名）
python3 ./example/high_level/read_highstate.py enp2s0
# ③ 运动测试：站立/趴下、速度控制、姿态控制（择一放开注释）
python3 ./example/high_level/sportmode_test.py enp2s0
#   test.StandUpDown()      站立与趴下
#   test.VelocityMove()     速度控制（低速起步！）
#   test.BalanceAttitude()  姿态控制
# ④ ROS2 侧：source 环境后验证状态与状态机
source ~/unitree_ros2/setup.sh
ros2 topic echo /sportmodestate
# 运动状态：mode/gait/velocity
ros2 topic echo /lowstate
# 底层状态：关节、IMU、电池
ros2 topic echo /wirelesscontroller
# 遥控器摇杆 lx/ly/rx/ry 与 keys
# ⑤ 站立示例（example 工作空间编译后）
cd ~/unitree_ros2/example && colcon build
./install/unitree_ros2_example/bin/go2_stand_example
安全闸门：
VelocityMove 示例速度按官方写法跑即可，课堂自行改参数时
把线速度压到最低档、先空旷后狭窄
；狗出现抬腿异常/连跌趋势，立即让它趴下（lieDown 模式）再排查。任何时刻遥控器在手。
控制走哪条路
高层：SDK/Ros2SportClient 组 Request → 发到 /api/sport/request，运动服务统一执行。
状态走哪条路
运动服务广播 /sportmodestate 与 /lowstate，订阅即可，不用轮询。
为什么用 DDS
ROS2 与 Go2 底层同为 CycloneDDS，话题可以直连，不必二次封装。
验收判据
同一脚本三连：站起→低速直线+转向→趴下，状态话题全程无丢帧即为通过。

速度越快、地面越滑，这条线越不能抖
，这正是「低速起步」的物理原因。

08
常见问题
课段 8 · 融会贯通 · 13 min
Q pip 报 Could not locate cyclonedds？
cyclonedds==0.10.2 没装好：按 README 本地编译 cyclonedds，再 export CYCLONEDDS_HOME 指到 install 目录重装。
Q ros2 topic list 是空的？
三查：网段是否 192.168.123.x、setup.sh 里网卡名是否写对、RMW_IMPLEMENTATION 是否 rmw_cyclonedds_cpp 且已 source。
Q 狗不听速度指令？
先看 /sportmodestate 的 mode：处于手动/阻尼等非 locomotion 态会拒答；确认运动服务在线、无 App 抢占。
Q 指令一发就猛窜？
示例里残留了较大的目标速度：把 VelocityMove 参数压回最低档再跑，牢记低速起步、预留急停空间。
Q 没有真机怎么练？
source setup_local.sh 用回环接口跑 ROS2 流程，状态话题用录包回放；运动真操环节统一上真机。
Q 要用 App 额外操作吗？
高层 SDK 模式用默认运动服务即可；只有跑底层 low_level 控制前才需在 App 关闭 sport_mode，避免指令打架。
Q 前置相机怎么取帧？
unitree_sdk2py 提供 example/front_camera/camera_opencv.py（需图形界面，ESC 退出），EXP-04 拍照复用它。
Q 遥控器数据能读吗？
能：订阅 /wirelesscontroller 得 lx/ly/rx/ry 摇杆量与 keys 键值，可做手动接管的二次判据。
