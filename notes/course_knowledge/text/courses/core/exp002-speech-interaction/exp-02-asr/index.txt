声学模型 ASR 语音识别：把声音变成文字
唤醒之后，机器人必须"听清你在说什么"。本实验围绕
sherpa-onnx + Zipformer-Transducer
流式识别链：100ms 微块送入 encoder、RKNN 模型跑在 RK3576 NPU 上、endpoint 三条判停规则决定何时出完整句，再用
热词表 + beam search 调参
把"左转"听成"转收"的尴尬压下去，最后以 WER 字错率量化验收。

01
问题引入：从"声音"到"文字"隔着多远
EXP-01 让机器人"听见有人叫它"，但喊完"小飞小飞，前进"之后——
后半句去哪了？
阵列的 ivw 唤醒事件只带一个词，真正的话还在空气里飘。把话变成文字，机器人会遇到三难：
1
连续性
：声音是河，文字是桥——如何在说话中途就"边流边译"，而不是等说完才处理
2
一词多听
："shi/zi/si"不分、环境噪声干扰，同音字让裸识别错误率居高不下
3
何时算完
：你停顿 2 秒是在想词，还是说完了？停顿判定错，句子被拦腰截断
4
算力有限
：工控主机没有 GPU 独显，识别必须跑得又快又省
💡 解法总览
课程选用
sherpa-onnx
（ONNX 推理框架 + 丰富的流式模型生态）+
Zipformer-Transducer
模型，模型量化为 RKNN 后用
NPU 加速
；配合热词、判停规则与解码参数三组旋钮解决上面四难。
02
原理通俗讲解：听写员的三道工序
生活比喻：会议速记员。
你说话时，速记员不是等你整段讲完才动笔，而是边听边写、时不时回头修正。一条 ASR 管线就是三位接力的工人：
1
前端特征工 = 磨面
：原始波形每 100ms 切一块，转成声学特征（FBank/MFCC）——就像把麦子磨成面粉，扔掉音色保留"能识别内容的信息"
2
声学模型 = 听写员
：Zipformer（Transformer 变体）盯着特征序列，输出"此刻最可能在发哪些音"的概率
3
解码器 = 终审编辑
：Transducer 的 joiner 把声学概率与语言先验合并，beam search 保留 Top-N 条候选路径，边走边吐字
4
判停 = 编辑画句号
：endpoint 三规则判断"你说完了"，固化输出并清空会话状态
模块
生活类比
本实验对应
流式分块
边吃火锅边涮，不等一桌菜全熟
每 100ms 一段喂入 encoder，首字延迟可感知地低
声学模型
听写员的"耳朵+拼音功底"
Zipformer encoder 输出音素级概率
语言模型先验
编辑的"语文语感"
解码器偏好常见词组；热词即"给编辑划重点"
hotwords 热词
生僻人名预先写在稿纸上
hotwords="前进 后退 左转"
，权重 hotwords_score=2.0
endpoint 判停
编辑看你停笔多久才画句号
rule1 静音 4.5s / rule2 尾部静音 1.5s / rule3 最长 300s
WER 字错率
校对统计错字率
(替换+删除+插入)/总字数，越低越好
🔍 关键概念：Transducer
传统"声学模型→字典→语言模型"三件套是接力赛；Transducer 把声学与解码
端到端联训
，中间不再查字典 —— 少一次翻译，错一次少一层传播。代价是训练更讲究，但推理侧更紧凑，正适合边缘部署。

09
重点与易错点
🎯 本实验三重点
① 流式管线的"块-模型-解码-判停"四拍；② 热词只在
modified_beam_search
下生效；③ WER 是唯一的裁判 —— 任何调参都要用数据说话。
⚠️ 常见坑
现象 → 解法
热词不起作用
热词设了照样错 → 检查 decoding_method 是否 greedy（贪心直接忽略热词词汇）
句子被截断
话没说完就出 final → rule2 尾静音阈值调大，或说话中途停顿超过 rule1
半天不出句
说完没反应 → 把 rule1 4.5s 调小做实验，观察灵敏度/准确度权衡
声卡找错
识别到笔记本内置麦 →
arecord -l
重新核对编号，用
plughw:N,0
而非 default
增益过小/爆音
小声识别差 / 大声全是毛刺 → 调 PGA 数字增益 + ALC 自动电平，波形峰值保持 1/3~1/2
rknn 加载失败
provider=rknn
报错回退 → 确认 /dev/rknpu 存在、sherpa-onnx==1.10.0 与模型格式匹配
版本混装
pip 升级后模型加载器报符号错误 → 锁定版本重装，不要与旧版 so 共存
实时识别出字速度跟得上语速，partial 持续更新、endpoint 后输出 final
热词组 vs 非热词组的 WER 对比表已记录，能解释数字变化的原因
三组 endpoint 参数的截断/拖沓故障均已人为复现过一次
rknn 与 cpu 两组延迟/占用数据入表，能说出 NPU 加速的实际收益
识别"左转"等指令能被 COMMAND_MAP 命中并打印动作名

📝 思考题 1
热词机制本质是给词"加钱"。若业务指令扩到 500 词，几乎覆盖整个词表，加钱还有效吗？请从 beam 候选打分的角度论证，并给出替代方案（提示：语言模型 / 语法约束解码 / 两级识别）。
📝 思考题 2
rule1 的 4.5 秒"静音判停"和人类"说完即止"的直觉差很远。结合课堂对话场景算一算：每轮回复要白等多少秒？怎样既不截断句子又快速判停？（提示：主动句末标点检测 + VAD 联动，与 EXP-04 的 VAD 期权衡呼应。）
