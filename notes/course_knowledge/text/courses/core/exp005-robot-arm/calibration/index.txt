δ (μs) → 角度偏差 = δ ×
0.002356
rad/μs  例：+70μs ≈
+9.4°
校准后发送：
PWM_send = PWM_target(rad 转来) − δ
// δ = 实际中位 PWM − 1500，所以发送时要把它减掉
为什么"±9.4°"在指尖会放大成几厘米：
J2 的偏差会把整条大臂+小臂+工具（0.126+0.126+0.151 ≈ 0.40 m）一起转过去，臂越远放大越多——顶端 9.4° 的角误差 ≈ 0.40 × 0.164 rad ≈
6.6 cm
；J3 只影响小臂+工具（≈0.28 m），同样 9.4° 也有 ≈4.5 cm。
这就是"手臂看着只歪一点点、抓取却偏一大截"的原因
：角误差在关节处很小，在末端被连杆长度放大。
反过来给一个现场口径：想让末端控制在 5 mm 内，J2 允许角误差 ≈ 5 mm ÷ 403 mm ≈
0.0124 rad ≈ 0.71°≈ 5 μs
——5 μs 只有 1 个 PWM 刻度（舵机理论分辨率约 2.4 μs）的两倍，所以校准"再来一轮精调"不是吹毛求疵，而是被几何放大的必然要求。
生效边界（读码发现，务必讲到）：
全仓库
servo_offsets.yaml
只被 calibration 包的 GUI/服务读写，
arm 控制链（arm_controller / kinematics）并不自动加载它
——所以① GUI 里的 Apply 是"会话内补偿"；② 长期生效要回到第 4 步"归零验证 + 各链路各自偏置"；③ 这正是讲义坑表"校准后仍不齐 → 多轮迭代"的深层原因。
和第 4 部分（手眼）的顺序：
零位管"每个关节从哪算 0"，手眼管"相机装在哪"。零位没校，手眼标定时采的每个 T_ee 都带着同样的歪——AX=XB 会把一部分歪悄悄吸收进 X 里，
换个位姿又露馅
。所以顺序永远是：先第 1 部分，再第 4 部分。

PART 2 · TCP 标定（四点法）
2 · TCP 标定（四点法）：工具尖端在哪，落点就该在哪
教学目标：
① 理解 TCP（Tool Center Point）= 法兰坐标系之后的等效工具点，不标 = 换姿态就画圆；② 掌握
四点法
原理与最少条件（≥4 组不同姿态、同一尖点）；③ 会做四点法的最小二乘解算与弥散验收；④ 看懂仓库里 0.033 / 0.215 这些 TCP 常数从哪来。
🎯 案例（代码 · kinematics/config.py + 讲义实验5 工具清单）：
仓库里的 TCP 不是理论值而是
标定产物

FINGERTIP_OFFSET_Z = 0.033
（
实测值

TCP_OFFSET_Z = 0.0762
（实测 76.25 mm）、
Y_TCP = 0.215 mm
（IK 里那个 asin 补偿的真身）。
注意别把它们和
gripper_depth
混为一谈
：33 mm 是"指尖比 tcp_link 低多少"的
几何常数
；
gripper_depth
是"抓取点相对检测面再挪多少"的
运行参数
（yaml 实配 −0.040 是抬高 40 mm）。两者单位都是米，含义完全不同——很多同学会以为 −0.033 就是来自这 33 mm，那是巧合，不是因果。讲义实验5 的标定工具清单：

装尖点
：把尖笔（或锥销）固定在夹爪中央，代替正常工件——现在"工具尖"就是待标定的 TCP。
顶四个姿态
：控制机械臂从
≥4 个明显不同的姿态
（俯仰至少差 30°+）让尖端触到
同一个
图钉孔/纸上小点，每到位一次记录关节角。
FK 算法兰
：每个姿态用正运动学得到法兰原点 p_i 与姿态 R_i（这就是 demo 里点 P₁~P₄ 的由来）。
解四点方程
：四组
p_i + R_i·t = c
（c 未知、是同一个尖点）——两两相减消 c，最小二乘解工具偏移
t = (t_x, t_z, t_y)
，写回 config 的 TCP 常数。
弥散验收
：再换任意姿态重复顶点，若计算出的尖端都落在同一点（弥散 ≤ 纸上一点），TCP 标定通过。
交互 · 四点法台：姿态一换，未标的偏移就"画圆"
每个姿态 i：已知
p_i, R_i
（FK），求
t（TCP 偏移）
使下式对所有 i 成立：
p_i + R_i · t =
c
（同一个尖点，未知）
≥4 组 → 两两相减消 c → 线性方程组最小二乘解 t（本台 2D 简化：平面 p+t）
真实 TCP Δx
+8mm
真实 TCP Δz
+33mm
你"以为"的 Δz′
+0mm
∫ 四点法求解（对齐 Δz′）
↺ 回到未标定
读图与判定
怎么看：
灰色小方块 = 四个姿态下的
法兰原点
（FK 得到、彼此不同）；红叉 = 用"你以为的 TCP"推算出的四个尖端位置——只要
Δz′ ≠ 真实 Δz
（或 Δx 不为 0 时算错），四个红叉就摆成一个
圆
（画圆半径 ≈ 偏移误差）。点"四点法求解"后四个红叉塌缩到黑点（同一尖点），弥散读数归零——这就是标定完成的判据。
为什么恰好能解：
n 组位姿给 n 个向量方程，未知量只有 t（和 c）。两两相减把 c 消掉后，未知数个数不再随 n 增长——数据越多，最小二乘越抗单次 FK 误差。
姿态差异越大
（俯仰换着来），方程组越"硬"，条件数越好——这和第 4 部分手眼标定要"旋转多样性"是同一个道理。

没锥销就用图钉 + 硬纸板；工厂级四点法同理，只是位姿由示教器记录。本方法
只依赖 FK 已准
