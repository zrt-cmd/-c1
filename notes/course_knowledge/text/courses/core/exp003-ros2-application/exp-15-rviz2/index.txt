rviz2 三维可视化：机器人的"上帝视角"
RViz（Robot Visualization，机器人可视化）在 ROS 2 里的名字就是 rviz2——机器人开发的三维"取景器"：订阅激光点、TF 坐标轴、机器人模型、规划路径这些"空间话题"，实时画成三维画面，让
echo
里滚动的数字变成一眼看懂的图形。应用场景贯穿开发全线：装配阶段看 URDF 模型转没转、调试阶段看雷达点云装没装正、导航阶段看规划路径穿不穿墙，bag 回放验收也以它为统一窗口。本课从 Fixed Frame 讲到七大核心 Display。
难度 ⭐⭐
2 学时
验证性
关键词 rviz2 · Fixed Frame · Display · TF 可视化
目标
本课学完，你应该能做到
① 说清架构
OGRE + Display 插件
能阐述 rviz2 基于 OGRE 渲染引擎与 Display 插件体系的架构——为什么需要"以坐标系为容器、以 Display 为图层"的三维可视化，以及 Fixed Frame 的核心地位。
② 掌握配置
七大 Display
能正确设置 Fixed Frame，并依次添加配置 RobotModel、TF、LaserScan、PointCloud2、Image、Path、Marker 七种 Display。
③ 独立完成
配置可复现
能用
rviz2 -d <config>
加载配置，调整后通过 File → Save Config 保存，实现调试环境一键复现。
④ 迁移应用
当标准可视化前端
在后续 bag 回放、URDF 模型验证、仿真可视化中，能把 rviz2 作为标准三维前端按需配置。

rviz2 把消息"画"进三维视口——调试 IMU/雷达/TF/模型的统一窗口
定义
rviz2
（ROS Visualization 2）是 ROS2 的三维可视化工具：订阅你关心的话题，把消息内容渲染成几何图形。它
不生产数据、不控制机器人
，只是一个"取景器"——所以画面异常时，问题通常在数据源（话题/TF）而不在 rviz 本身。

03
原理讲解
Fixed Frame 决定"上帝站在哪"
灵魂参数
Fixed Frame：观测基准系
它回答"相机架在哪个坐标系上看世界"。设成 map：整张地图静止，机器人在图上移动；设成 base_laser：机器人钉在原点，墙壁绕着车动。
所有数据都会被 TF 变换到这个系
再画。
变换链
TF2 逐层查找
雷达点云 frame_id=laser → 沿 laser→base_link→odom→map 链逐级算到 Fixed Frame。链上任何一环断裂，该 Display 立即报黄 "Transform [sender=unknown]"——这就是 rviz 满屏黄字的第一大原因。
刷新节奏
Frame Rate 30 + 按需重绘
默认每秒渲 30 帧。它只消费数据不驱动系统：把 Fixed Frame 改掉、关掉某个 Display，被调试的机器人毫发无损——放心折腾。
怎么设置 Fixed Frame（可照抄）
① 界面改（即时生效）
：Displays 面板顶部
Global Options → Fixed Frame
，下拉选或直接敲 frame 名。
② 随配置带入
：
rviz2 -d ~/ros2_ws/install/car1_description/share/car1_description/rviz/car1.rviz
（这份配置里 Fixed Frame =
base_footprint
）；导航配置
navigation.rviz
里是
map
。
③ 裸启默认
：
rviz2
无配置时默认
map
。回放联调时再加
--ros-args -p use_sim_time:=true
（用法详见 EXP-11）。
Fixed Frame 设成
画面效果
典型用途
map
地图静止，机器人在地图中移动
导航调试（默认值就是它）
odom
忽略全局定位漂移，看相对里程
检查里程计平滑度
base_link / base_laser
车体钉在原点，环境绕着车动
检查单传感器安装与标定
某个不存在的 frame
全屏黄 Warning，画面冻结
不用管——这就是下节诊断台要抓的症状
本课案例用法：04 节第 4 步加载 car1.rviz（Fixed Frame=base_footprint）看整车；导航实操切 navigation.rviz（=map）看全局——两份配置的差别就是观测基准换了。
失败模式
判断"rviz 坏了还是系统坏了"的分界线：
能把数据画出来的前提是"变换链通"
。任何 Display 变黄先查 TF（Add → TF 看坐标轴在不在），而不是先怀疑 rviz。TF 通了还有问题，才去查话题本身（有没有数据、QoS 配不配）——完整排查顺序见 04 节"黑屏诊断台"。

七大 Display 逐个拆
① 地基
Grid
默认就有的网格地面，提供空间标尺。
迷失视角时右键 → Reset View
一键回正——这是新手最该记的肌肉记忆。
启动默认就有 Grid——视口里那层灰色网格就是空间标尺
② 骨骼
TF
Add → TF 自动订阅 /tf 与 /tf_static，RGB 三轴画出每个坐标系，Show Names 显示名字。断链=某段坐标轴消失，比
view_frames
生成 PDF
实时
得多——PDF 是快照，TF 图层是直播。
TF 图层开满：每个坐标系一组 RGB 轴 + 帧名，断链即少一组
③ 外形
RobotModel
读 Description Topic（/robot_description）画网格式车体。需要三方协作：
URDF 定结构 → robot_state_publisher 按 /joint_states 算各 link 变换 → rviz 渲染
。调试可关 Visual 只留 Collision、调 Alpha 半透明看内部。
RobotModel 把 URDF 画成实体车体——关节动，模型跟着动
④ 感知
LaserScan
Topic 选 /scan，Size 约 0.03。极坐标点变换成 3D 空间点，Color Transformer 按距离映射颜色（近红远绿）。前提：frame_id 必须在 TF 链上，否则黄字。
LaserScan 面板：Topic 指向 /scan，车周红点即一圈雷达点
⑤ 点云
PointCloud2
深度/视觉相机的点云。fields 描述每点的打包结构，RGB 常按 FLOAT32 打包——结构对不上颜色就乱。数据量大时调降 Point Size、抽稀订阅。
PointCloud2 渲染成果：密集点按强度/高度上色的三维空间
⑥ 规划
Path
nav_msgs/Path 折线，如正弦的 /plan。
算法对不对，曲线一眼定
：折角突变=规划抽风，路径穿墙=代价地图有洞——比读坐标数组快两个数量级。
Path 图层（左面板第 6 项）订阅全局规划，绿线画在地图上
⑦ 标注
Marker
万能便签：SPHERE/ARROW/TEXT_VIEW_FACING/Cube/LineStrip 形状，action 分 ADD/DELETE/MODIFY，
ns+id
定位实例。想在画面里标"目标点 3"？发个文字 Marker 即可，不用给 rviz 写插件。
Marker 大全家：球/立方/箭头/线条/文字——一个图层全画出来
配置资产
.rviz 文件
File → Save Config As 导出全部 Display 设置；下次
rviz2 -d xxx.rviz
一键还原。团队共享后，新人开箱即是同款调试视图——配置是工程资产，进 git。
三方协作链
RobotModel 不显示时，按数据流逆向查四步：①
ros2 topic echo /robot_description --once
（URDF 在不在）→ ②
ros2 node list | grep state_publisher
（rsp 活没活）→ ③
ros2 topic echo /joint_states
（关节数据来没来）→ ④ Fixed Frame 是否与 link 树根连通。外加
check_urdf
校验模型语法。

本课总结与验证题
定位
取景器，不是数据源
rviz2 只订阅、变换、渲染；异常优先查话题与 TF，而不是怀疑视图工具。
灵魂
Fixed Frame 是观测基准
一切数据变换到它才绘制；换帧=换视角，地图系看全局、车体系看感知。
图层
七 Display 按需叠加
Grid/TF/RobotModel/LaserScan/PointCloud2/Path/Marker 各管一维，按图层隔离故障。
资产
.rviz 配置进 git
团队共享调试视图，与 launch、params 一样属于可复现工程资产。
