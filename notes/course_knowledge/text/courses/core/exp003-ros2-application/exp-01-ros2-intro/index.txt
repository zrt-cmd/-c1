💡 一句话定义
ROS（Robot Operating System）
不是操作系统
：不管理硬件，它是一个
通信框架 + 工具集 + 包生态
，运行在 Linux 之上，为机器人软件提供"进程之间如何说话"的标准答案。
简单来说，
ROS2 = 机器人的
"普通话 + 微信群 + 一键工具箱"
——谁写的应用都能插上就跑，多台电脑自动成网。本课所有内容，都是在拆解这句话。

调用往下走 · 数据回程往上走

5 操作系统层
真实操作系统与网络设施，ROS2 只是跑在它上面的普通程序。
本课程统一用 Ubuntu 22.04
；官方同时支持 Windows 10+ 与 macOS，但装法、路径、终端习惯都不一样
本节下半的 source 三板斧，验证的就是这层环境通没通

能，但
不建议在本课程的实验里直接用它们
。ROS2 的三个平台不是"三套等价安装"：Linux 是官方一等公民（二进制包齐全、教程最全、机器人硬件驱动原生支持）；Windows 需要额外的 Visual Studio 与包管理环境，很多示例（turtlesim、rqt、部分驱动）跑不顺；macOS 支持面更窄，社区基本靠源码编译。

最省事，推荐
）；② Windows 用 WSL2 + Ubuntu 22.04（命令完全一致，图形界面需额外配置）；③ 直接用课程提供的实验箱。macOS 用户建议直接上虚拟机跑 Ubuntu。

换语言动第 2 层，换 DDS 实现动第 4 层，其余层原封不动。

06
源码一撇：发布订阅关键代码逻辑
刚才跑通的那两个节点，代码其实只有几十行。下面是你刚执行的
demo_nodes_cpp
官方示例的真实源码（已精简掉版权头和组件注册宏），重点看
发布
与
订阅
这两条主线各自靠哪几行动作完成。
共 4 件事
任何 ROS2 节点都一样
① 继承 Node → ② 起个名字 → ③ 建发布/订阅 → ④ 有消息就回调。
关键差异
只有 3 行不同
talker 是 create_publisher + 定时器发；listener 是 create_subscription + 收到就打印。
📤 talker.cpp —— 每秒说一句话
#include "rclcpp/rclcpp.hpp"          // ROS2 C++ 客户端库
#include "std_msgs/msg/string.hpp"      // 消息类型：字符串
class
Talker :
public
rclcpp::Node
// ① 任何节点都继承 Node
{
public
:
  Talker() : Node(
"talker"
)
// ② 节点名就叫 talker
{
// ③ 建一个发布者：往 "chatter" 这个话题上发 String
pub_ = create_publisher<std_msgs::msg::String>(
"chatter"
, 10);
// ④ 每秒触发一次，发一条编号递增的消息
timer_ = create_wall_timer(1s, [
this
]() {
auto
msg = std_msgs::msg::String();
      msg.data =
"Hello World: "
+ std::to_string(count_++);
      RCLCPP_INFO(get_logger(),
"Publishing: '%s'"
, msg.data.c_str());
      pub_->publish(msg);
// ← 发布动作：把消息推上 chatter
});
  }
private
:
size_t
count_ = 1;
  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr pub_;
  rclcpp::TimerBase::SharedPtr timer_;
};
📥 listener.cpp —— 收到什么就打印什么
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"
class
Listener :
public
rclcpp::Node
// ① 同样继承 Node
{
public
:
  Listener() : Node(
"listener"
)
// ② 节点名叫 listener
{
// ③ 建一个订阅者：盯住同一个 "chatter" 话题
sub_ = create_subscription<std_msgs::msg::String>(
"chatter"
, 10,
      [
this
](std_msgs::msg::String::ConstSharedPtr msg) {
// ④ 回调
RCLCPP_INFO(get_logger(),
"I heard: [%s]"
, msg->data.c_str());
      });
// ← 回调：每收到一条就执行一次
}
private
:
  rclcpp::Subscription<std_msgs::msg::String>::SharedPtr sub_;
};
🔍 把两份代码叠在一起看，会发现什么
两个类
结构完全一样
：继承 Node、给节点起名、连到
chatter
。唯一的差别是：talker 用
create_publisher
主动往外发，listener 用
create_subscription
被动等消息。
它们从头到尾没有互相"认识"过
——没有任何一行代码写着"我要连 listener"。这就是这一节最想让你看到的事：
连接是 DDS 在背后自动配对的，不是代码写的。
对比项
talker
listener
节点名
"talker"
"listener"
关键 API
create_publisher
create_subscription
话题名
"chatter"
← 两边必须写成一样，否则接不上
消息类型
std_msgs::msg::String
← 类型也必须一致
何时动作
定时器每秒触发一次
收到消息时被回调
主动/被动
主动发送
被动等待
💡 不用会写，先看得懂
本实验不要求你会写 C++。你只需要能从代码里认出
四个东西
：节点名、话题名、消息类型、是发还是收。后面学 Python 写节点时，会发现换成
rclpy
之后结构一模一样，只是语法不同——
话题、类型、发布、订阅这四个概念是跨语言的
