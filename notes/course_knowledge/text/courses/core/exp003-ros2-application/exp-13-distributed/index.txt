ROS2 分布式通讯：域隔离、组网与安全

本课的重点与难点
重点
：四级选型判据——规模有多大、网是怎样的（有线/无线）、要不要统一话题名；对应四招：域号划圈、namespace 寻址、XML 单播绕障、服务器集中。
难点

01
问题引入：好好的机器人为什么会"串台"
先回忆
EXP-05 讲过节点靠"网络组播"互相发现、EXP-06 讲过话题不经过任何中心服务器、EXP-12 已把域模型（
ROS_DOMAIN_ID
划圈）讲透——教学环境正是靠它给各组划圈，好让大家都统一叫
/cmd_vel

1
场景
同一教室三台 B2 实验车同时开机，全部使用 ROS2 默认配置
2
怪事

4
本质
ROS2 没有中心注册表，靠
网络组播
互相发现——同域 = 同一个"频道"
定义
域（Domain）
是 ROS2 的逻辑通信隔离圈：只有
ROS_DOMAIN_ID
相同的节点才能互相发现和通信。ID 取值 0~232，不同域的节点即使插在同一根网线上也"互相看不见"。这是 DDS 层的机制，ROS1 需要换 Master 地址才能做到的事，ROS2 改一个环境变量就行。
事故复盘：一次真实的"串台"

03
原理讲解
一个数字如何隔离整张网
物理层根因
组播地址跟着 ID 走
Fast-DDS 根据域号计算出专属组播地址
239.255.0.N
和端口
7400 + N×250
。发往不同域的发现报文在
网卡层就被分流
，根本不会送到对方协议栈——这就是隔离的第一道防线。
发现流程
SPDP 宣告 → SEDP 交换
节点启动即向域内组播地址周期发送 SPDP 发现报文；收到回应后双方通过 SEDP 交换"我有哪些话题/服务/动作端点"，才建立点对点的正式传输链。
对比 ROS1
去中心化的天然优势
ROS1 靠唯一的 ROS_MASTER_URI 注册中心，改域要换 Master 地址、全部节点重启；ROS2 每个节点自主发现，改 DOMAIN_ID 就是各改各的环境变量，Master 单点故障问题也随之消失。
组网三前提
同段、同 ID、组播通
跨机通信只依赖三件事：① IP 同网段（能互相 ping 通）② 双方 ROS_DOMAIN_ID 相同 ③ 组播没有被防火墙/交换机拦截。没有 Master、没有配置文件，就这三条。
对比维度
ROS1
ROS2（DDS）
发现方式

域内组播 SPDP 自主互发现
"隔离"手段
改 Master URI + 全节点重启
改 ROS_DOMAIN_ID，即时生效
取值范围
无域概念（一台机器一个 Master）
0~232，共 233 个逻辑隔离域
单点故障
Master 挂了新节点进不来
无中心，任意节点退出不影响他人
隔离层次
应用层（还能互相 ping）
直达 DDS 发现层甚至网卡过滤
和 VLAN 的本质区别
VLAN 是交换机上的
硬件隔离
——报文不在同一广播域，要动网络设备配置；域是 DDS 发现层的
软件隔离
——报文照样到达网卡，只因组播地址 / 端口不同在
网卡分流层
就被丢弃。交换机一动不动，改一个环境变量即时生效。
要点
三台机器人要"各自独立"，最简单的规范是：
每台机器人烧录不同的 DOMAIN_ID
（写进
~/.bashrc
或机器人系统镜像），中央工作站同时开多个终端、用不同 ID 分别接入各车——比给每台车配独立网段省事得多。

两种发现模式与通信安全
模式一 · 默认
组播自主发现
开局域网、机器人数量少（<50 节点）时的默认选择。零配置、即开即用，但依赖组播——部分企业网/云环境交换机禁用了组播，就全军覆没。
模式二 · 进阶
ROS_DISCOVERY_SERVER 单播
指定一台"发现服务器"，所有节点改为向它单播注册。不受组播限制，适合 50~500 节点、跨子网、云端混合部署。代价是要先启动并维护 server 进程。
安全层
DDS-Security / SROS2
DDS 标准定义的安全扩展：governance（哪些域要加密）+ permissions（谁能发/收哪个话题）+ passwords（密钥），ROS2 封装为 sros2 工具包，未授权节点连"看到话题"都做不到。
成本意识
加密是有代价的
SROS2 Enforce 模式带来约 5~15% CPU 开销。教学小车资源有限，建议：内网实验默认不开，涉及远程遥控/OTA 升级的产品化场景再启用。

SROS2 速览
三步启用：①
sros2 security generate_artifacts -p governance.xml -p permissions.xml -k keystore
生成密钥库 ② 每个节点启动时注入

③ enclave 名必须与 permissions 声明一致。效果：未授权节点 echo 会直接失败。⚠ 密钥库严禁提交 git。

第一级 · 教学分组
整组换域号，话题名统一
实训室 6 组同时上课：每组发一个域号（
1~6
），组内全部光明正大叫
/cmd_vel
、
/chatter
——异组之间本来就互相看不见，串台在分组这一层就死掉。这就是我们教学统一用

第二级 · 同网群控
同域加 namespace 前缀
同一组 6 台 B2 要联动：进入同一域后，各车话题挂上前缀
/robot01/cmd_vel
…
/robot06/cmd_vel
——指哪打哪是"按车寻址"，循环 6 个前缀发一遍就是"群发全组"。
第三级 · 无线组控
XML 固定对端，单播宣告
车跑起来靠实训 AP：802.11 对组播按最低速率发、不重传还聚合限速，SPDP 宣告一多就随机丢——把固定几台的 IP 写进一份 Fast DDS XML，宣告逐台单播直达，发现不再赌无线组播。
第四级 · 大规模机群
服务器集中 + 主备容灾
开放日 40 台车跨教室联调：静态名单已经写不动、组播更会形成发现风暴——全部节点改为向 DISCOVERY_SERVER 单播注册，部署两台 server 一主一备，主挂备切，发现链路不断。

概念
域 = DDS 层逻辑隔离圈
ROS_DOMAIN_ID 0~232，同号互通、异号隔离，对应专属组播地址与端口。

只要三个前提
同网段、同域号、组播畅通。排查顺序：ID → ping → multicast → 防火墙 → 换 RMW。

教学分组用域号、同网群控用 namespace、无线组控改 XML 单播、大规模机群上 DISCOVERY_SERVER 主备容灾。
工程化
隔离要落到镜像里
每台机器人出厂烧录独立域号，中央站多 ID 接入——这是多机车间的标准姿势。
