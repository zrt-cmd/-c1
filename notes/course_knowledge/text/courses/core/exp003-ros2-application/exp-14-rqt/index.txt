EXP-14 · 第四章 · 验证性 · 2 学时
rqt 可视化工具箱：GUI 调试工作台
对着终端敲 echo、grep、awk，是命令行侠的浪漫，但效率有天花板。rqt 是 Qt 插件化调试工作台：图形看拓扑、曲线看波形、图像看画面——把"查/看"两件事从终端搬进 GUI。本课讲清插件架构原理，用本机真实话题（底盘电压、相机图像）实战核心插件。
难度 ⭐
2 学时
验证性
关键词 rqt_graph · rqt_plot · rqt_image_view
目标
本课学完，你应该能做到
① 说清设计
为什么要插件化
能阐述 rqt 基于 Qt 插件框架的设计原理——为什么把多个调试工具整合为可组合面板，比"开一堆独立窗口"在机器人开发中更高效。
② 掌握主力
graph + plot
能熟练用
rqt_graph
画节点-话题-服务拓扑诊断通信链路，用
rqt_plot
实时绘制任意话题字段的曲线看时序趋势。
③ 独立排查
日志过滤 + 动态提级
能用
rqt_console
按 DEBUG/INFO/WARN/ERROR/FATAL 五级过滤日志快速定位问题节点，并用
ros2 service call .../set_logger_levels
动态提级、抓完调回。
④ 迁移成流程
先看图再看曲线
把"先 rqt_graph 定位拓扑异常，再 rqt_plot 确认数值趋势"当成标准调试流程，用在后续实验里。
本课的重点与难点
重点
：
rqt_graph
的读图能力——它能把"我以为连上了"和"实际没连上"一眼区分开。
难点
：rqt_plot 采样率不足会产生"假波形"（奈奎斯特），别把显示问题误判成数据问题。
和前后的关系

定义
rqt
是基于 Qt 的插件化调试工作台：本体只提供菜单、停靠窗口和插件管理，所有功能（画图、过滤、看日志……）都是可热插拔的插件。你看到的 rqt_graph、rqt_plot 等不是六个软件，是
同一个容器里的六个窗口
——可以按需拼装、保存成布局（Perspective）一键还原。四层怎么叠、怎么装怎么开，见 03 节

rqt_plot 主窗口——左上=话题路径+勾选框，主体=随时间滚动的电压曲线
照着截图怎么读：
①
左上角控制条

②
曲线区横轴
——滚动的

③

——

④
曲线右端点
——当前最新值，应与

出的数（如 11975）基本一致——GUI 看趋势、CLI 定数值，两边对得上才下结论；
⑤
本案例判读
——1Hz 的缓变信号在图上是一条缓慢起伏的基线；给小车上电/断电让电压变化，曲线应实时抬头/下压。

03
原理讲解
插件化架构为什么好用
承接 01 节"把命令行工具装进同一个图形界面"——先看四层怎么叠，再把"怎么装、怎么开"的入口抄走。
图 14-1 · rqt 插件架构｜本图回答：rqt_graph / rqt_plot 们为什么共享同一套话题、切工具不用重连？
✅ 结论：一个容器共享一套上下文，切换插件零重连
⚠️ 风险：未 source 同源环境 → 插件菜单缺失 / 图为空
🔍 验证：04 节启动三连 + graph/plot 交叉印证

失败模式
：没 source 同源环境 → 菜单里找不到插件、图空白（05 节坑表"graph 图是空的"）。
容器层
Qt 主窗口 + 插件发现
rqt 启动时扫描
/opt/ros/humble/share/rqt_*
下声明的插件入口，动态加载进菜单。写一个自己的 rqt 插件，就能把私有调试界面挂进官方工具箱。
数据层
共享同一个 ROS 上下文
所有插件共用 rqt 进程内的 ROS 节点——你在 rqt_graph 里看到的图，和 rqt_plot 订阅的是同一套话题系统，无需逐个工具重新连接。
组合层
Perspectives 布局保存
窗格停靠、插件组合、参数设置可整体存成 Perspective。排查导航问题存一个、调试串口存一个，切换工作场景一键还原，团队共享布局文件保持排查口径一致。
分层哲学
GUI 预览，CLI 定案
rqt 定位是"快速看"：graph 3 秒找断点、plot 秒级看趋势。脚本化/CI 场景仍回 CLI（ros2 topic echo / ros2 param）。GUI 提效率，CLI 保可复现，别二选一，要各司其职。

五大核心插件逐个拆
① 拓扑
rqt_graph
Plugins → Introspection → Node Graph。椭圆=节点、矩形=话题、箭头=数据流。
Hide Debug
勾上，/parameter_events、/rosout 消失，主链路一目了然。右上 Refresh 手动刷新——节点动态变化时不会自动重绘。
读图要点：椭圆=节点、矩形=话题，箭头去向即数据流方向；顶部工具条 Hide Debug 勾选态可见。
② 波形
rqt_plot
Visualization → Plot。路径必须写全
/topic/field
，如
/car1_base_driver/battery/data
（不带字段不出线；String 字段不可绘）。"加号"按钮从话题树选字段最稳；还支持数学表达式
/a/data + /b/data
合成曲线。
读图要点：Topic 栏填话题路径，图例显示展开后的字段（如 /cmd_vel/data）——路径必须写到字段级才出曲线。
③ 图像
rqt_image_view
Visualization → Image View。订阅
sensor_msgs/Image

奈奎斯特提醒
rqt_plot 画采样信号时，采样频率至少是信号频率的 2 倍才能还原波形（奈奎斯特采样定理）。1Hz 正弦波用 0.5Hz 采样画出来会变成一条"低频假波"——GUI 不会替你报警，请自己心里有这根弦。这也正是 EXP-11 讲

命令行管日志的一个技巧
只筛 WARN 往往还会被海量 INFO 之外的同级 WARN 淹没——用
grep -E "node_a|node_b"
做多关键词 OR 收窄；反过来若怀疑"问题起因在 INFO 里"，就先把 grep 放宽、再顺时间线往上游找。提级后
一定记得调回
，DEBUG 刷屏会拖慢实时节点。
06
本课总结与验证题
架构
容器 + 可插拔插件
rqt 本体只是 Qt 工作台，多个核心插件共享同一 ROS 上下文，Perspectives 保存布局。
分工
插件各管一维
graph 看结构、plot 看波形、image_view 看画面、topic 看数据、bag 看回放。
边界
能 CLI 就别开 GUI
日志过滤、动态提级用 ros2 topic echo /rosout 与 set_logger_levels 服务——本机现成、可脚本化、更好复现。
心法
交叉验证
曲线冻结别只信 plot，拓扑断流回 graph——GUI 给速度，CLI 给确定性，两边互相印证。
验证题（改动型 · 每题先自己作答，再展开核对）
1（目标①·改变启动方式）
把原本在
rqt
容器里同时打开的 rqt_graph 与 rqt_plot，改成两个独立终端各跑一次
ros2 run rqt_graph rqt_graph
和
ros2 run rqt_plot rqt_plot /car1_base_driver/battery/data
——两个窗口看到的是同一套话题吗？容器方式多出来的一项能力是什么？
参考答案与得分点
得分点：①是——插件与容器各自连的都是同一套 DDS 话题系统，看到的拓扑/数据一致（图 14-1 数据层） ②容器方式多了 Perspectives 布局保存与"切插件零重连"（进程内共享同一 ROS 上下文），独立进程各建各的节点、无法拼进同一布局。（① 40%，② 60%）
2（目标②·改字段路径）
rqt_plot 里把
/car1_base_driver/battery
改成话题名
/chatter
（std_msgs/String），曲线区会怎样？要画
/odom
里 x 随时间的变化，路径应填什么？
参考答案与得分点
得分点：①String 不可绘——曲线区不出线（或提示无法绘制） ②必须写到字段级：
/odom/pose/pose/position/x
③选字段更稳的办法是点"加号"从话题树里选。（①②各 40%，③ 20%）
3（目标③·改级别数值）
把提级命令里的
level: 10
改成
level: 50
再执行，节点日志会变多还是变少？若提级到 10 抓完问题却不调回，会有什么后果？
参考答案与得分点
得分点：①50=FATAL——只剩致命错误，日志比 INFO（20）更少 ②10=DEBUG 不调回 → 全量调试日志刷屏、拖慢实时节点（05 节红线） ③正确姿势：抓完改回
level: 20
。（①②各 40%，③ 20%）
4（目标④·改排查顺序）
按图 14-3，有人跳过"hz 验活"和"graph 判连"直接开 rqt_plot，看到曲线冻结不动——他可能把什么误判成什么？正确的下一步是什么？
参考答案与得分点
得分点：①会把"话题没数据 / 发布端没起"（没连接）误判成"plot 卡死或数据异常"（显示问题） ②正确顺序：先回
ros2 topic hz
验活、
ros2 node list
查发布端 ③顺序不能倒：先判"有没有"，再判"对不对"。（① 40%，②③各 30%）
5（目标②④·改数据幅度）
实测电压从 12.0V 缓慢降到 11.8V，rqt_plot 里却看起来"剧烈震荡、快没电了"。改什么、查什么能确认这是显示问题而不是数据问题？
参考答案与得分点
得分点：①纵轴自适应会把 0.2V 的变化放大成满屏摆动——先看左侧刻度，不只看形状 ②用
ros2 topic echo /car1_base_driver/battery --once
拿精确值，与曲线右端比对（图 14-3 的 CLI 定案步） ③两边说的是同一件事才下结论：GUI 看趋势，CLI 定数值。（① 40%，② 40%，③ 20%）
