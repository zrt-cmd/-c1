定义
rosbag2

调试成本从"去现场"变成"回工位"
，硬件依赖型调试工作量可压缩 80% → 20%。

存储结构
SQLite3 双表 + 元数据
一个 bag = 目录：
*.db3
数据库 +
metadata.yaml
清单。库里两张表——
topics
（话题ID→名称/类型/QoS）与
messages
（时间戳+话题ID+CDR 字节流）。YAML 记录时长/条数/相对路径，删除它 bag 就"失忆"。
为什么选 SQLite
四条硬理由
① 自带索引→任意时间点随机访问；② 事务机制→写到一半断电最多损坏最后一笔；③ SQL 直接聚合分析（频率=Count/Duration）；④ 单文件好搬运好上传。
序列化
CDR：和 DDS 同一种字节
存的就是 DDS 线上传输的 CDR 序列化结果——回放时零转换直接发出，语义 100% 保真。这也是为什么 rosbag2 不需要每种消息写专用适配器：只要类型支持接口定义，就能录能放。
两个缓冲别混
max-cache ≠ max-size
--max-bag-size
：
单位是字节
，单文件写满自动切分新 .db3（控制磁盘文件粒度）；
--max-cache-size
：内存写盘缓冲（调小→高频消息排队溢出
丢数据
，默认 100MB 够用，4K 相机再加大）。

选择
理由

scan/imu/camera + odom/tf + cmd_vel + 关节——修复故障的最小证据链

🔎 是什么
两族参数的
分工
：
record
管"录什么、录多大、压不压"（范围 + 体积 + 编码）；
play
管"怎么放"（节奏 + 时间 + 话题选择）。
❓ 为什么
因为录制与回放面对的是
两套不同的约束
：录制时受磁盘与 CPU 限制（要控制体积），回放时受下游算法与渲染限制（要控制节奏与时间基准）。所以参数族必然分成两队。
🛠 怎么用
录：

。

ros2 bag play 名字 -r 倍速 --topics 话题 --clock
。
记住三条硬规则
：限时用 timeout、play 选话题用 --topics、压缩必须双参数。

本课总结与验证题
结构
SQLite 双表 + YAML 清单
topics/messages 两表 + CDR 原始字节，索引支撑随机访问，事务保断电不损。QoS 存在 topics 表的
offered_qos_profiles
列。
录制
点名 + 正则是生产标准
-a 磁盘秒爆（还混入 /rosout 等系统话题）；点名圈最小证据集，配双参数压缩、--max-bag-size 分片、--max-cache-size 缓冲。
停止一律用 Ctrl+C
（优雅写盘），
kill -9
会丢缓存并损坏 SQLite。
回放
改节奏不改时间戳
-r 倍速、--loop 循环、--start-offset 跳段、--topics 选话题（无 -t）；TF 静态必 loop。回放结束 Publisher 销毁属正常。
离线流
--clock（约40Hz）+ use_sim_time
play 带钟、节点与 rviz 认钟、Time 面板验钟——三步跑通"把现场带回工位"。验钟要用带 header 的话题。
三问一句话收束
是什么
：把话题的时间序列 + CDR 字节录进 SQLite 双表，配一份 metadata.yaml 清单。
为什么
：现场故障只来一次，数据流过即消失。录下来才能把"去现场"变成"回工位"，把一次性调试变成可重复回归。
怎么用
：
record
（点名 + timeout + 可选压缩）→
info
（用真实 Duration 心算频率验完整性）→
play
（-r / --topics / --start-offset / --clock）。
三条硬规则
：限时用 timeout 不用 -u；选话题用 --topics 不用 -t；压缩必须 mode + format 双参数。
