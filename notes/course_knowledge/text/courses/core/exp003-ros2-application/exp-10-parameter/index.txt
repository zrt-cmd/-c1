EXP-10 · 第 2 章 · 设计性 · 2 学时
参数服务：把配置参数从代码里拉出来
PID 系数、采样周期、报警阈值——硬编码意味着"改参 = 改码 → 编译 → 部署"。本课讲清参数作为"运行时可读写配置层"的原理、declare/get/set 生命周期与动态回调闭环。

参数是什么（俗称"旋钮"）
参数是节点内部状态的
运行时可读写配置层
：不定义通信通道、没有消息类型流转，直接读写节点内存变量——这与话题（异步数据流）、服务（同步 RPC 操作）有本质区别。
"旋钮"只是个比喻
：说的是它像音量旋钮一样"随时能拧、拧了立刻生效"，具体到代码里，它就是节点上一个个有名字、有类型的值（如
publish_period=1.0
）。
03
核心原理：声明 → 读取 → 设置，与两次校验
声明 declare
登记存在 + 默认值 + 类型
declare_parameter('publish_period', 1.0)
在 __init__ 执行一次；
默认值同时决定类型
（1.0→float，1→int）。参数服务将声明注册，使 CLI / rqt 能发现它。
读取 get
任意时刻取当前值
self.get_parameter('name').value
——启动时读一次缓存进成员变量，或在每次回调里现取，都不受限制。

period_desc = ParameterDescriptor(

'MQ5 数据发布周期（秒），越小采样越快。'

    floating_point_range=[
        FloatingPointRange(from_value=0.02, to_value=10.0, step=0.01)
    ]

ParameterDescriptor
声明时登记的元数据

# 来源：param_sensor_node.py timer_cb（使能开关 + 阈值报警两处消费参数）
def timer_cb(self):
    if not self.sensor_enabled:
# 消费点①：使能开关——false 时直接返回，
return
#   定时器仍在走，只是采样被"跳过"（功耗极低）
raw, v, ppm, err = read_mq5_once()
# 复用实验6 的真实 MQ5 读取
msg = Float32(); msg.data = float(ppm)
    self.pub.publish(msg)
    if ppm >= self.alarm_threshold:
# 消费点②：阈值判断——参数一改，下一拍就用新值
self.get_logger().warn(
f'[报警] ppm={ppm:.2f} >= {self.alarm_threshold}ppm'
)
    else:

第三站 · 回调：校验 → 应用 → 回执
# __init__ 末尾注册（必须先导入：from rcl_interfaces.msg import SetParametersResult）
self.add_on_set_parameters_callback(self.on_parameters_set)

def _recreate_timer(self):
"""按新的发布周期重建定时器 —— 参数真正改变行为的关键一步"""
self.destroy_timer(self.timer)
    self.timer = self.create_timer(self.publish_period, self.timer_cb)

def on_parameters_set(self, params):
"""params: 本次被修改的参数列表（可能一次多个）"""
for p in params:
        if p.name ==
'publish_period'
:
            if p.value < 0.02 or p.value > 10.0:
# ① 校验：范围外一票否决
return SetParametersResult(successful=False,
                    reason=
f'publish_period 必须在 [0.02, 10.0] 内，收到: {p.value}'
)
            self.publish_period = float(p.value)
# ② 应用：更新变量
self._recreate_timer()
#    + 重建定时器（行为才变）
self.get_logger().info(
f'发布周期已更新: {self.publish_period} s'
)
        elif p.name ==
'sensor_enabled'
:
            self.sensor_enabled = bool(p.value)
        elif p.name ==
'alarm_threshold_ppm'
:
            if p.value < 0.0:
                return SetParametersResult(successful=False, reason=
'报警阈值不能为负数'
)
            self.alarm_threshold = float(p.value)
    return SetParametersResult(successful=True)
# ③ 回执：每个出口都必须返回

本课总结与思考题
定位
运行时配置层
不走数据流、不走 RPC，直接门卫式读写节点内存——与话题/服务三足鼎立。
生命周期
declare → get → set
声明一次定型定类；get 随取；set 必过回调。
动态闭环
callback 三件事
校验、应用（重建定时器）、回执 SetParametersResult——缺则"改了没用"。
工程化
Descriptor + YAML
描述符自描述供 UI 渲染；dump/params-file 让参数配置即代码。
思考题
① 手动回调校验与 ParameterDescriptor 范围两层约束，CLI 越界时哪一层先触发？设计一个实验（如把两层范围设成不一致）验证你的判断。
② 巡线小车 PID 三参数相互关联，改 Kp 后需要重置积分累计值防"积分突变"——_on_param_changed 该怎样处理一次 set 两个参数的场景？是否要连带重置 Ki/Kd 的累计？
③ 参数服务回调在参数服务线程而非主线程执行——这对"回调里做模型加载"这类重活意味着什么？给出两种改造思路。
