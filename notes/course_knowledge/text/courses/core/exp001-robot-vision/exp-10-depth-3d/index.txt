EXP-10 · 第 4 阶段 · 人体感知 · 设计性 · 4 学时
深度相机：让机器知道「那东西离我多远」
前面所有实验都只知道「东西在画面的哪个位置」，但不知道「它在多远」。这个实验给机器人加上第三只眼 —— 深度相机。点一下画面上的任意像素，程序就能告诉你「这个点离你 0.48 米」，还能算出它在真实空间里的三维坐标。

01
这个实验解决什么问题
CORE IDEA · 一句话原理
普通相机只给你
方向
（在画面哪个位置），深度相机还给你
距离
。有了这两样，就能算出三维坐标。
打个比方：
你在房间里听到有人喊你名字。光靠耳朵，你只知道「声音从右前方传来」。如果对方同时告诉你「我离你 3 米」，你就能准确指出他的位置。
深度相机就是那个会说距离的相机。
为什么机器人必须有深度？看三个真实任务：
任务
只有 2D 会怎样
有了深度
机械臂抓杯子
知道杯子在画面中间，但不知道要伸多远 —— 可能抓空，可能撞翻
算出杯子的 (X, Y, Z)，直接过去
小车避障
看到前面有个东西，不知道是 30cm 还是 3m —— 该停还是该走？
小于 50cm 就停，稳
3D 建模
只能得到一张照片，没有立体信息
每个像素都变成一个空间点，拼成点云
本实验的目标：
双栏看到彩色图和深度图；点画面上任意一点，程序报出「距离多少米 + 三维坐标 (X, Y, Z)」。
02
三分钟讲懂：怎么从一张图算出距离
核心只有一个公式，而且很好理解。先把「相机怎么把三维世界拍成二维图」想清楚，反着推就是答案。
针孔相机模型：一个三角形相似就够
相机
光心
成像平面（照片）
像素 (u,v)
物体
(X, Y, Z)
Z 轴（光轴）
f 焦距
Z 深度（深度相机直接测出来的）
u = fx·(X/Z) + cx
v = fy·(Y/Z) + cy
↑ 正向：世界 → 照片（相机在干的事）
↓ 反向：照片 + Z → 世界（本实验要干的事）
X = (u − cx)·Z / fx
图 8-1｜上半是「拍照」，下半是「反推」。本实验做的就是下半那个反向过程。
反投影公式，逐个字母看懂
📐 三个公式
X = (u − cx) × Z / fx
Y = (v − cy) × Z / fy
Z = 深度值 ÷ 1000
（相机给的单位是毫米，换成米）
符号
叫什么
本实验的实际值 / 含义
u, v
像素坐标
你点的那一点在画面里的行列号。范围是 u ∈ [0, 639]、v ∈ [0, 479]（640×480 图）
Z
深度
深度相机直接测出来的
，不是算出来的。单位毫米 → 除以 1000 变米
fx, fy
焦距（内参之一）
这块相机标定出来的值：
fx=608.40
、
fy=611.21
。
单位是像素
，不是毫米
cx, cy
主点（内参之一）
光轴打在画面上的位置：
cx=328.30
、
cy=226.46
。不是正好 320/240，因为镜头装配有偏差
X, Y
横 / 纵坐标
算出来的结果，单位米。
X 向右为正，Y 向下为正
（相机光学坐标系约定，不是数学课本的 y 向上）
⚠️ 关键认知：Z 不是算出来的
很多人以为深度是「算」出来的。
不是。
深度相机有一路专门的红外发射+接收（结构光或 ToF），
直接测量
每个点的距离。反投影公式只是把这个测量值配合像素位置，换算成三维坐标。
没有深度相机的普通相机，永远算不出绝对距离
—— 它只能从「同一个物体在不同距离下看起来大小不同」做单目估计，误差很大。
为什么 fx 是 608 而不是「50 毫米焦距」？
这是初学者最容易被卡住的一点。相机规格书上写着焦距 3.6mm 之类的数字，但配置里 fx=608 ——
两者不是同一个单位
：
fx = f（物理焦距，毫米）÷ 单个像素的边长（毫米）
所以 fx 的单位是
像素
。它回答的问题是：「当物体离我 1 米、横向偏 1 米时，它在画面里偏离中心多少像素？」
把 fx 换算成「看多宽」会更直观 —— 这就是
视场角 FOV
：
# 水平视场角（度）
FOV ≈ 2 × arctan(width / (2·fx)) = 2 × arctan(640 / (2×608.4)) ≈
54.9°
# 垂直视场角
FOV_v ≈ 2 × arctan(480 / (2×611.2)) ≈
43.0°
所以这台相机大概能看「正前方左右各 27°、上下各 21.5°」的范围。
fx 越大 = 视角越窄 = 看得越远越清楚
（长焦）；
fx 越小 = 视角越宽
（广角）。
同一个像素偏移，fx 越大算出的实际偏移越小
—— 这就是下面参数实验台要你亲手验证的事。
为什么要标定？
因为 fx、fy、cx、cy 由镜头的
实际制造
决定，不是算出来的。cx=328.30 而不是 320，说明镜头装配有约 8 个像素的偏心。
这几个数错了，所有三维坐标都会系统性偏移
—— 这正是本实验最重要的收获。
算一遍给你看
假设你点了画面正中心偏右一点的位置
(u=400, v=240)
，深度相机测到 Z = 0.5 米：
# 已知内参
fx = 608.39958    fy = 611.20714
cx = 328.30096    cy = 226.46483
# 反投影
X = (400 − 328.30) × 0.5 / 608.40 =
0.0589 米
← 往右 5.9 厘米
Y = (240 − 226.46) × 0.5 / 611.21 =
0.0111 米
← 往下 1.1 厘米
Z =
0.5 米
← 前方 50 厘米
结果：那个点在你前方 50cm、右边 5.9cm、下方 1.1cm 的位置。
机械臂可以直接朝这个坐标伸过去。
一句话记住：
像素告诉你「朝哪个方向看」，深度告诉你「看多远」，内参告诉你「镜头的几何长相」。
三者合起来，就能从一张照片定位空间中的一点。
03
先认识 4 个词
深度图
depth
一张只有距离信息的图。每个像素存的是「这个点离我多少毫米」，不是颜色。用 16 位无符号整数（uint16）存，理论上限 65535mm ≈ 65 米。
0 表示「测不到」
。
内参
intrinsics
相机的「身份参数」：焦距 fx/fy（像素单位）+ 主点 cx/cy（光轴落在画面的哪个像素）。每台相机出厂都不一样，必须标定才知道。
反投影
从 2D 像素 + 深度，反推出 3D 坐标的过程。就是上面那三个公式。
点云
把所有像素都反投影一遍，得到几十万个三维点。用 MeshLab / CloudCompare 打开能转着看物体的立体形状。
深度图为什么用伪彩色显示？
选读 40 秒
因为深度值（0~65535 毫米）直接显示成灰度图，人眼根本分不出层次 —— 近处和稍远处都是一片灰糊，这也是灰度图对比度天生不够的问题。
所以程序先做一件事：
把有效深度值线性拉到 0~255
（min-max 归一化，无效的 0 值不参与统计），再套上
JET
色表。
JET
的约定是
数值低 = 蓝，数值高 = 红
。归一化后「近 = 数值低」，所以：
JET 在本实验的读法：蓝 / 青 = 近 → 绿 = 中 → 黄 / 红 = 远
为什么近处是蓝不是红？
因为归一化把较小的深度（近）映射到较小的灰度值，而
JET
又把较小的灰度值映射到蓝色。这条链路决定了方向 ——
是「先归一化再套色表」这两步共同决定的，不是色表单独决定的
。
配置里
colormap: jet
就是干这个，也可以改成
gray
看灰度版（灰度版近处暗、远处亮，方向反过来，更难读）。
注意：伪彩色只是给人看的
。程序内部做计算用的始终是原始的毫米数值 —— 颜色和真实距离之间还隔着一次 min-max 归一化，两者不是固定对应关系（场景一变，同一个蓝色可能代表不同距离）。
⚠️ 一个容易踩的坑
无效像素（深度=0）归一化后也是 0，
在 JET 里显示为深蓝
—— 和「最近处」撞色了。所以看画面时要结合形状判断：
大片纯深蓝的斑块通常是「测不到」，不是「贴到镜头上」
。这也是「画面 B」要专门讲的原因。

06
你该看到的画面
画面 A · 双栏正常
左彩色 右伪彩
右栏颜色随距离连续变化（蓝 → 青 → 绿 → 黄 → 红）。
平滑的渐变 = 深度测量正常
；如果右栏大片纯色或颜色跳变，说明有问题。
画面 B · 深蓝或纯黑斑块
深度 = 0（无效）
这些是「测不到」的地方：玻璃、镜面、太远、太近、或者物体表面太黑吸收了红外。
深蓝 ≠ 「最近」，这里是无效像素恰好也是深蓝
—— 结合形状判断。
画面 C · 边缘模糊
物体轮廓处颜色渐变
这是深度相机的固有特性 —— 物体边缘处红外光会有一部分打到背景上，测出的深度是「混着的」。所以边缘的深度值不可靠。
🔍 为什么无效像素不能当「距离 0 米」？
深度值 0 是一个
约定
，表示「这个像素没有有效测量」。如果程序把 0 当成「距离 0 米」，反投影算出来的点会全部堆在相机位置上 —— 这就是点云图里常见的「一团乱点」来源。
正确处理：反投影前跳过 Z=0 的像素。

进阶（可选）
进阶 1 · 生成一张点云图
约 40 分钟
把画面里每个像素都反投影一遍，得到 30 万个三维点（640×480）。存成
.ply
或
.xyz
文件，用 MeshLab 或 CloudCompare 打开，就能转着看立体形状。
for v in range(480):
    for u in range(640):
        Z = depth[v,u] / 1000.0
        if Z == 0: continue                      # 跳过无效
        X = (u - cx) * Z / fx
        Y = (v - cy) * Z / fy
        points.append((X, Y, Z))
注意两个性能问题：
① 纯 Python 双循环很慢，实际要用 NumPy 向量化；② 30 万个点里可能有大量噪点，通常要按深度范围过滤或降采样。
进阶 2 · 抠掉背景，只算桌面的高度
约 30 分钟
一个很实用的技巧：
深度图可以直接当「分割」用
。
比如要找一个桌上的物体，先测出桌面的深度（比如 0.8m），然后把深度 < 0.78m 的像素全部取出来 —— 这些就是「比桌面高的东西」。不需要任何 AI 模型。
这个思路在工业上非常常用
：如果场景固定、光照可控、物体总是比传送带高，深度阈值比任何深度学习方案都更快更可靠。
进阶 3 · 为什么深度相机测不到玻璃和镜子
选读 1 分钟
HP60C 这类深度相机用的是
红外结构光或 ToF
：发出一束红外光，等它反射回来，用「飞了多久」或「花纹变形多少」算距离。
玻璃为什么不行？
红外光直接穿过去了，没反射回来 —— 相机等不到回波，只能给 0。
镜子为什么不行？
光被整片反射到别处去了，回到相机的方向是错的 —— 测出来的是一个「虚像」的距离，甚至更远。
黑色物体为什么不行？
黑色吸收红外，回波太弱，信噪比不够。
所以工业上做 3D 检测时，被测物表面通常要处理：喷哑光粉、贴哑光胶带、或者改用激光三角测量。
这些「物理层面的对策」，往往比调算法更有效。
进阶 4 · 为什么深度相机需要「对齐」到彩色相机
选读 1 分钟
HP60C 的彩色镜头和红外深度镜头
在物理上差了几厘米
。这意味着深度图里第 (320, 240) 个像素，和彩色图里同一个位置的像素，
看的不是空间中的同一个点
。
不做对齐会怎样？你把彩色图里检测到的目标中心 (u, v) 直接拿去查深度图，读到的可能是目标背后的墙的距离 ——
误差在物体边缘处最明显
。
解决办法是
深度-彩色对齐
（depth-to-color alignment）：用两个镜头的内参和外参（相对位置），把深度图重投影到彩色相机的视角下。对齐后两图逐像素对应，才能安全地「彩色找目标 → 深度查距离」。
怎么判断是否已对齐？
拿一个手指伸到镜头前，看彩色图和伪彩深度图里手指的轮廓是否重合。如果深度图里的手指明显偏移或错位，就是没对齐。
本实验的
ascamera
驱动输出的深度话题已是标定对齐过的，所以直接查值即可。
换用第三方深度相机时，这一步必须自己确认。
