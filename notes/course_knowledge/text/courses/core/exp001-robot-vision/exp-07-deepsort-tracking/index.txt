多目标跟踪：让"同一个人"在视频里一直是 3 号
检测每帧都在跑，但每帧都是独立的 —— 这一帧的 3 号，下一帧可能变成 7 号。跟踪要解决的就是这件事：
把跨帧的框串成"轨迹"
，让每个人从头到尾一个 ID。更难的是：人被挡住几秒再出现，还得认出是同一个。

01
这个实验解决什么问题
CORE IDEA · 一句话原理
每一帧都做一道
"连线题"
：把这一帧的框，接到上一帧的哪条轨迹上？
打个比方：
就像看球赛时盯着一个球员。球跑得再快、被别的球员挡住一下，你还是知道"那个人"是谁 —— 因为你
记得他刚才在哪、也记得他长什么样
。DeepSORT 用的就是这两条线索。
先看清问题：如果没有跟踪，会怎样？
帧
检测结果
问题
第 1 帧
框 A 在人身上
还行
第 2 帧
框 B 在人身上
这是同一个人的框吗？不知道
第 3 帧
框 C 在人身上
完全不知道这 3 个框是不是一个人
下游任务全都依赖"ID 稳定"：
人流统计
要数"经过了几个人"，ID 一跳就多算一个人；
行为分析
要判断"这个人停了多久"，ID 变了就断了；
跟人走
要一直跟同一个目标，ID 变了就跟丢了。
本实验的目标：
画面里三个人各有一个固定编号，来回走动、互相交叉、短暂遮挡之后，编号都不变。

三分钟讲懂：怎么给同一个人一直贴同一个号
DeepSORT 每帧只做四件事。理解了这四件事的
顺序
，你就理解了这个算法。
每一帧都在重复这四步
① 猜"它现在在哪"
按上一帧的速度外推
Kalman filter
② 算"配得上吗"
轨迹\检测
A    B    C

T2
0.7  0.2  0.6
T3
0.9  0.7  0.3
数字越小 = 越像同一个人
外观 + 位置
③ 挑"最划算的配法"
整体代价最小的方案
匈牙利算法
④ 贴新号
ID 3
ID 7
未匹配
匹配上的沿用旧号
两条线索缺一不可：
· 只看位置 → 两个人一交叉就换号（这叫 sort，配置里可以切换对照）。　· 只看外观 → 穿同款衣服的两个人会混。
图 7-1｜四步循环。其中第②步同时用位置和外观两条线索 —— 这是 DeepSORT 里的 "Deep"。
两条线索分别是什么
线索一 · 位置
他刚才往哪个方向走、多快
用
Kalman 滤波
推算"这一帧他应该在哪个位置"。人在画面里是连续移动的，所以这个猜测通常八九不离十。
+
线索二 · 外观
他穿什么衣服、体型什么样
用
ReID 模型
把每个人的框压缩成一个 512 维的"指纹向量"。同一个人的指纹很接近，不同的人差得远。
把两条线索合成一个"代价"（越小越像），再交给匈牙利算法找全局最优配对：
# 概念示意，不是真实代码
代价 = 0.2 × 位置距离  +  0.8 × 外观距离
#     ↑ 权重小，因为人会突然转弯   ↑ 权重大，因为衣服不会突然换
被挡住了怎么办
情况
程序怎么处理
靠的是哪个参数
人走进树后，看不见了
轨迹
不删除
，继续用 Kalman 猜位置，编号保留
max_age: 70
（最多等 70 帧）
人从树后出来
凭外观指纹认出是同一个，恢复原 ID
ReID +
max_dist: 0.2
等太久没出现
超过 70 帧就删掉这条轨迹
max_age
刚出现的新目标
先观察 3 帧，稳定才给正式编号
n_init: 3
一句话记住：
先猜位置（Kalman），再看长相（ReID），然后整体配对（匈牙利）。
猜错位置时靠长相救回来，长相相似时靠位置区分开
—— 这就是两条线索的意义。
03
先认识 4 个词
轨迹
track
一条"命的记录" —— 包含一个 ID、一串历史位置、一个外观指纹。匹配上就更新，太久没匹配上就删除。
Kalman 滤波
一套"用历史推测现在"的数学方法。不神秘：
用上一帧的位置 + 速度，推这一帧的位置
。
匈牙利算法
解决"怎么配对总代价最小"的经典算法。3 条轨迹配 3 个检测，有 6 种配法，它负责挑最优那一种。
ReID
Re-Identification，重识别。把一个人的图像压成一个特征向量（指纹），用来判断"是不是同一个人"。
为什么叫"级联"匹配（cascade）？
选读 50 秒
因为匹配是
分批做
的，不是一次性做完：
先让"最近一帧刚出现过的轨迹"去匹配（它们最可靠），匹配完剩下的检测，再让"已经丢失 1 帧的"去匹配，然后是丢失 2 帧的……
按"新鲜度"从新到旧一轮一轮来。
为什么这么设计？
假设有两条轨迹同时竞争一个检测：一条是刚刚还在的目标，一条是丢了 30 帧的。
应该优先给刚出现的那个
—— 因为丢太久的那个可能早就离开画面了。级联匹配就是这个优先级的体现。

做遮挡实验：这是本实验的核心
约 8 分钟
这一步必须做，因为它才对得起"DeepSORT"这个名字。
操作：
先确认配置里是

框消失，但 ID 还"记着"（等它回来）

ID 恢复原来的数字  ✅ deepsort 正常
拿开后：
ID 变成了一个新数字  ✗ 需要检查
现在改成

nano
config/track_config.yaml
# tracker.mode: deepsort → sort
sort 模式：
挡住再出现 → ID 几乎必然变成新号码 ❌
为什么？
因为 sort 只有位置线索。人消失了几秒，位置完全没法推测（可能从任何方向出来），只能当新目标处理。

这个对比实验做一次，比读十遍文字说明都管用。

进阶 1 · 做一次人流统计
约 40 分钟
在人流统计里，"经过"的定义是：
某个 ID 的框中心，从画面左侧穿过中线到了右侧
。
维护一个集合 seen = set()
每帧遍历所有 track：
    如果 track.id 不在 seen 里，且 中心x > 中线x：
        count += 1
        seen.add(track.id)
关键在于那个
seen
集合
—— 它保证同一个 ID 只被数一次。这就是"ID 稳定"为什么这么重要的最直接例子：ID 一跳，同一个人就被数成两个。

(帧号, ID, 中心x, 中心y)

进阶 3 · 为什么不能只用一个更强的检测器解决 ID 问题
选读 1 分钟
初学者常有的困惑：如果把检测器做得特别准，是不是就不需要跟踪了？
不能。
因为检测器天生是"无记忆"的 —— 它每次只看一帧，输出的是"这一帧有什么"。它
没有
"上一帧有什么"这个概念，所以根本无从知道"这个框是不是上次那个"。
跟踪提供的正是这种
跨帧记忆
。这不只是精度问题，而是
能力维度的缺失
—— 就像一个人视力再好，如果没有记忆，也认不出"刚才见过的那个人"。
所以跟踪的价值不在"更准"，而在"能维持身份"。这也解释了为什么跟踪是一个独立的研究方向，而不是检测的附属功能。

随堂小测
Q1
目标被挡住 2 秒后重新出现，deepsort 能恢复原 ID，sort 不能。为什么？
因为 sort 跑得更慢
因为 deepsort 有外观指纹，能认出"还是那个人"；sort 只有位置线索，遮挡后位置无从推测
因为 sort 的模型参数少
对。
遮挡期间位置完全不可知（可以从任何方向出来），所以位置线索失效。这时唯一能依靠的就是"他长什么样"—— 也就是 ReID 的外观向量。
Q2
n_init: 3
是什么意思？
最多跟踪 3 个目标
连续 3 帧都检测到，才确认为正式轨迹并给编号
初始化要花 3 秒
对。
这是防误报的设计。如果某一帧闪了一下误检，程序不会马上给它编号 —— 要连续稳定 3 帧才认。
Q3
画面里两个人穿一模一样的黑衣服并排走，跟踪容易出错。主要该调什么？
把 max_age 调到 200
这时外观线索变弱，要更依赖位置 —— 检查 max_iou_distance 是否够用，必要时收紧外观门限
换一个更大的检测模型
对。
这是 DeepSORT 的经典弱点：外观相似时指纹区分不开，只能靠位置。所以配置里
max_iou_distance
的注释特意提到"0.7 移动中易丢轨迹" —— 位置门限太紧，移动快时就匹配不上了。
两条线索的权重需要按场景权衡。
