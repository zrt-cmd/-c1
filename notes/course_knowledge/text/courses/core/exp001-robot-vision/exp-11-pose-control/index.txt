02
三分钟讲懂：动作怎么变成车轮转速
两个关键点：① 怎么把"举手"变成数字判断；② 怎么把"动作"变成小车认识的两个数。
第一关：怎么判断"举手"
最直觉的想法是"手腕比肩膀高"。但直接比 y 坐标有个大问题：
情况
直接比 y 坐标
用归一化
人站在 3 米外
整个人都很小，y 值挤在一起，"举手"和"没举"差不了几个像素
比值不变，照样判断正确
人站在 0.5 米近
y 值跨度很大，随便动一动就超过阈值 → 误判
比值不变
换成小朋友
体型不同，阈值全不对
比值不变
解决办法：用身体自身的尺寸做单位。
把"髋部中点"当原点，"髋到肩的距离"当 1 —— 所有坐标都换算成这个单位下的值。这就是
_norm()
干的事。
# 概念示意，不是真实代码
身长 = |髋中点 − 肩中点|
# 这个距离作为"1 个单位"
# 归一化后的高度（0 = 髋部，1 = 肩膀，1.5 = 头顶以上）
手腕高度 = (髋中点y − 手腕y) / 身长
# 判断规则就变成了"比值比阈值大"
if 手腕高度 > 0.72:  举手
这个 0.72 就是从经验里试出来的：手举过头顶通常落在 0.8~1.3，正常站着在 -0.5 左右。
用比值的好处是：这个 0.72 对谁都适用
—— 高个子矮个子、站远站近，都用同一个阈值。
第二关：举手怎么变成车能听懂的话
ROS 里控制小车只需要两个数：
linear.x
往前走多快（米/秒）
正数 = 前进
，负数 = 后退，0 = 不动。配置默认 0.2 m/s。
+
angular.z
转多快（弧度/秒）
正数 = 左转（逆时针）
，负数 = 右转，0 = 不转。默认 0.8 rad/s。

⚠️ 最容易搞反的地方
"举左手 → 左转"，很多人会写成
angular.z = −0.8
。但 ROS 约定是
逆时针为正
。从上方往下看，车往左拐就是逆时针转 —— 所以左转是正数。
这一条记不住就多试两次，试错比背公式快。
第三关：多个动作同时满足怎么办
现实里经常出现这种情况：你双手举起来，同时手腕也在肩膀上方 —— 算"双手举"还是"举左手"？
解决办法：给规则定优先级。
复杂/明确的动作优先，简单的兜底。
🔍 本实验的优先级顺序
1. 下蹲
（最特殊，髋部位置变化明显，先判）
2. 双手举
（要求两只手都高，比单边严格）
3. 举左手 / 举右手
（单边）
4. 停止
（兜底，什么都不满足时）
为什么这么排？
因为"下蹲"这个姿态很独特：人蹲下时髋部会大幅下降，同时手腕也可能相对变高。
如果先判"举手"，蹲下时就会被误判成举手
。所以特殊动作要先判。
三句话总结整个实验：
① 用身长归一化，让判断不受距离影响；② 用一张 if 规则表，把姿态翻译成两个速度数；③ 用优先级，解决多规则同时命中的冲突。
03
先认识 4 个词
cmd_vel
ROS 里控制移动底盘的标准话题名。消息类型是
geometry_msgs/Twist
，里面就
linear
和
angular
两组数。
发布者 / 订阅者
ROS 的通信方式：一方往话题里写（发布），另一方从话题里读（订阅）。
它们互相不认识，只认话题名。
优先级
多条规则同时命中时，谁说了算。本实验是"特殊动作优先，停止兜底"。
归一化
把坐标除以身长，变成"身体的倍数"。这样不同身高、不同距离的人用同一套阈值。
为什么板端还要"clamp"（限幅）？
选读 30 分钟
配置里注释写"车 clamp ±0.3 内"。意思是：
不管上层发多大的速度，车端会强制压到 ±0.3 以内
。
这是一道安全防线。假设程序 bug 发了
linear.x = 5.0
（5 米/秒对小车来说是飞出去），车端会自己压成 0.3。
上层出错的代价被限制住了。
这种"最后一层兜底"的设计在机器人里很常见：
不要在唯一的控制点上赌正确性，要在能兜底的地方加保护。

不确定 = 停

09
进阶（可选）
进阶 1 · 加去抖动，让动作稳定
约 30 分钟
问题：站在阈值附近时，动作会在两个值之间闪。车跟着抽。
最简单的解法：连续 N 帧都是同一个动作，才真的切换。
候选动作 = classify_action(...)
if 候选动作 == 上一个候选:
    连续计数 += 1
else:
    连续计数 = 1
    上一个候选 = 候选动作

if 连续计数 >= 3:        # 稳定 3 帧
    当前动作 = 候选动作
这 6 行代码能显著改善体验。
代价是响应变慢了几帧
—— 又是一个取舍。
进阶 2 · 用"手的位置"连续控制速度
约 40 分钟
现在是"离散控制"（要么走得快，要么停）。更自然的是
连续控制
：手举得越高，车开得越快。
手高度 = 归一化手腕高度
速度 = clamp((手高度 − 0.4) / (1.2 − 0.4), 0, 1) × 最大速度
这样手在手在胸口时慢慢走，举过头顶时全速。
这就是"比例控制"的思想
，和 EXP-03 里"偏移量 × 系数 → 角速度"是同一个结构。
但要注意：连续控制更难停稳。手一抖速度就变 —— 所以还是需要去抖动。
进阶 3 · 为什么要先上 turtlesim 再上真车

真实的机器人开发流程就是这样：
仿真验证 → 低速真机 → 正常速度
。每一步的成本差一个数量级。

Q1
"举左手 → 小车左转"，
angular.z
应该是什么符号？
负数，因为左是负方向
正数，ROS 约定逆时针为正，往左拐就是逆时针
0，转向不用 angular
对。
从上方俯视，车往左拐时是逆时针旋转，而 ROS 规定逆时针为正。所以左转 =
正
角速度。
这个符号几乎每个人都会搞反一次
，记不住就试一次。
Q2
为什么判断动作前要先用"身长"归一化坐标？
为了让计算更快
因为人站远站近、高矮不同，绝对坐标差很多，而比值不变
因为模型输出的就是比值
对。
如果直接比 y 坐标，排在 3 米外的人"举手"和"没举手"可能只差 5 个像素，阈值完全失效。除以身长之后，这个比值对任何距离、任何身高都适用同一套阈值。
Q3
为什么
publish_cmd_vel
的默认值是
false
？
因为默认值写错了
安全设计 —— 调规则、试效果时车不会突然动起来
因为 cmd_vel 话题不存在
对。
这是"默认安全"（fail-safe）的原则。
危险的默认值是关闭的，要用的时候显式打开。
这样即使有人直接跑起程序、改代码改出错，车也不会失控。这个设计思路比代码本身更值得学。
