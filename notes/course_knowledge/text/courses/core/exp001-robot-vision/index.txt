WHY THIS ORDER
为什么把 OpenCV 放在最前面
原顺序按「检测→分类→分割→跟踪→3D→人体」的技术版图排，但对初学者不友好：第一个实验就要碰 int8 量化和 NPU 部署。新顺序改成按学习坡度排 —— 从
不用训练、立等见效
的 OpenCV 开始。

SETUP
开课前要配好的三件事
① 每个新终端都要 source 两下
每开一个新终端，先跑
source /opt/ros/humble/setup.bash
和
source ~/ros2_ws/install/setup.bash
。只 source 第一个会找不到
ascamera
等自建包 —— 这是最高频的卡点。
② 所有终端用同一个域号
实时实验要先起相机
ros2 launch ascamera hp60c.launch.py
，然后每个终端都
export ROS_DOMAIN_ID=2
。
域号不一致 = 相机在发、程序在等
，症状是
ros2 topic list
一片空白。
③ 用浏览器看画面
板子没有显示器也能看结果：
http://<板IP>:8080/xxx.mjpg
。端口分配：实验 1~7 共用 8080（不要同时开），实验 8=8081、9=8082、10=8083、11=8084、12=8085。

BEFORE YOU START
三条通用约定，先记住
命令一律在实验目录下执行。
每个实验页第 05 节第一条命令都是
cd ~/ros2_ws/src/xflz_eai_car1/vision/<目录>
，因为配置文件和模型都按相对路径引用。
忘了 cd 是最常见的「找不到文件」
。
先起相机，再跑程序。
实时模式（
--ros
）依赖相机话题存在。顺序反了程序会一直等首帧然后超时，看着像「卡住」。
先看画面，再查数值。
每个实验都给了「你该看到的画面」一节。画面不对是采集/预处理问题，画面对但数值不对才是算法问题 ——
先分清楚这两类，排查效率差十倍
。
