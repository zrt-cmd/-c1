EXP-06 · 第 2 章 · 综合性 · 4 学时
VLM 描述选目标：一句「追踪红色小轿车」如何变成一个 ID
用户不会总记得 ID。当门控传回「有描述、无 id」时，VLM 网格登场：把当前帧切成带编号的缩略图网格、让
Qwen3.5-0.8B_vision
只答一个数字、再用
cell_ids[k-1]
把格子映射回追踪 ID。
cell_cap=16 的硬上限、0/99 拒答、三路径 fail-closed
共同保证"选不准就不锁"。

01
问题引入：说颜色怎么锁 ID
你说「追踪红色小轿车」，可系统内部流通的只有
DeepSORT 的数字 ID
（id18、id24…）。颜色词与 ID 之间隔着一道翻译鸿沟——LLM 只负责听懂并吐出
track_vlm
（EXP-05 第③口），真正"看图认车"的活落在 VLM 头上：
1
门控判定「描述有、id 无」→ track_vlm
2
dump_track_grids 给当前帧打上编号标签、切网格
3
VLM 只答一个数字（或 0 = 没找到）
4
cell_ids[k-1] 映回真实 ID → submit_effect 锁定
💡 为什么不直接报 ID
端侧 0.8B 视觉模型读小目标数字 ID 极易看错；网格化把它简化成
"选第几格"
的四选一选择题——正确率高得多，还天然可校验。
02
原理通俗讲解：先看缩略图再放大
VLM 网格就像先看缩略图再放大细节
——监控室值班员不是把每辆车放大数车牌，而是先在九宫格缩略图上圈"红色那格"，再看该格里的具体目标。
比喻一
切网格 = 贴号码牌的缩略图
build_grid（vlm_real.py L175-213）把帧切成 rows×cols 网格，每格标 1..n 的大号数字、空位标
?
，统一压到 448×448。
格子编号是给模型看的"座位号"。
比喻二
_pick_grid = 先排座再定座数
L170-185 按排序键
(|r-c|, 格子数, min(r,c), r)
在候选布局中挑一个——让网格尽量方正、优先 2×2 这类小布局，候选多了才升 4×4。
比喻三
PROMPT = 只许报座位号的考规
「图片是 R 行 C 列的网格…只答数字 1..N，找不到答 0」（grid_select_prompt L215-240）；
故意不提供 99 这个"逃生口"
（L218 注释）——模型答 0/99/越界一律按拒答处理。
比喻四
cell_ids[k-1] = 座位号换真人 ID
_parse_tile（L241-263）把「3」还原成 k=3，select_crops（L433-473）在 L471 取
cell_ids[k-1]
。
座位号 ≠ 追踪 ID
，这一步才是换算。
🔍 fail-closed 三路径
①VLM 懒加载失败 → None；②解析出 0/99/越界 → None；③候选目标 > 16（cell_cap=16）→ None。三条路殊途同归到
_vlm_none
（track_app.py L402-405，打 WARN + 引导话术、
绝不 submit
）——拿不准宁不放行。

09
重点与易错点
座位号 ≠ 追踪 ID
：格子 k 是给模型看的，真正 ID 必须经
cell_ids[k-1]
；直接把 k 当 ID 会锁错目标
cell_cap=16 是硬上限：候选框超过 16 个直接 None——宁可让用户换个描述，也不让模型在 16+ 格里盲选
0/99/越界一律拒答：_parse_tile 的宽容解析不是"尽力猜"，而是把所有歧义都送进同一条 fail-closed 路
VLM 是懒加载：第一次说颜色指令才实例化模型，首载 30-60s 内"没反应"是正常加载，不是卡死
实验完确认锁定状态再收尾：失败链路必须停在引导话术，锁定了 ID 说明门控或映射有漏
⚠️ 常见坑
现象 → 解法
选中格却锁了隔壁车
k 与 cell_ids 下标错位 → 核对 cell_ids[k-1] 与 _pick_grid 的 order 顺序是否一致
n=11 却仍是 2×2
先看 _pick_grid 排序键 (|r-c|, 格子数, …) 的输出 → 必要时读 dump JSON 的 order 字段
模型回了长句子不给数字
_parse_tile 解析不到 1..N → 按拒答处理进 _vlm_none，检查 PROMPT 是否完整下发
测试与真机结果不一致
fake_result_id=3 固定返回 → 跑真链路先清掉/留档假件再验
首载 60s 以为挂了
llm_mgr 30-60s 属正常 → 看「Qwen3.5-0.8B…--port 8080」拉起日志
