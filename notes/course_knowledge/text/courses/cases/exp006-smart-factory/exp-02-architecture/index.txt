01
问题引入：一个人干不完全场活
设想把"听指令、记任务、抓货物、转流水线、盯安全"五件事全写进一个 Python 文件会怎样？
1
语音 ASR 是阻塞的——听一句话的几秒里，安全检测停摆（
盯雷达的人去接电话了
）
2
任何一处异常拖垮整个进程：语音挂了，急停也跟着挂
3
改一处动全身：调个抓取参数要重启全部功能
4
解法：按
职责单一
拆成五个进程（节点），只靠
话题/服务
通信——单点可替换、可独立启停
💡 设计哲学
节点 = 责任田
：每块田只种一种庄稼（语音/调度/抓取/流水线/安全），田与田之间只走约定好的"路"（话题/服务）。这就是 ROS2 多节点架构的全部初衷：
让"改一处"只动一处，让"坏一处"只坏一处。
02
原理通俗讲解：餐厅后厨的分工与传菜
还是那家餐厅——五个后厨岗位就是五个节点，
传菜条与对讲机
就是两类通信方式：
🎙 前台迎宾 = N1 语音
只听懂话、不下厨
KWS 唤醒 → ASR 识别 → LLM 意图分类 → 往"点单屏"（intent 话题）写一笔，播报由 TTS 完成。它
从不直接动机械臂
。
🧑‍🍳 值班经理 = N2 调度器
唯一做决策的节点
盯着点单屏（intent），按任务分流：装货/分拣直接喊抓取（grasp/start 服务），码垛先喊传送带备料。
轻状态机，不干重活。
🤲 主厨 = N-grasp 抓取
只做"抓-放"原语
双模式：装货走视觉（AprilTag 定位），分拣/码垛走 yaml 固定点位八步法。完成发 status，
不自作主张接新任务。
🏭 传菜梯 = N-conveyor 流水线
电机 + 光电传感器
复用底盘电机 M1 + GPIO17 光电，run_until_sensor 转到遮挡就定点停，收到 danger 立即急停。
🛡 安全员 = N3 safety
常驻盯雷达、优先级最高
/scan 回调内算 60° 扇区最小距离，超限
当场双发
：放 danger 广播 + 释放 6 舵机力矩——不请示、不排队。
📡 对讲机 vs 提单 = 话题 vs 服务
异步广播 vs 同步确认
话题
像对讲机广播（intent/danger/status 随时插话，人人可听）；
服务
像提单办手续（发任务必须等回执 success）。秒级阻塞的抓取用服务拿确认，状态信号用话题保畅通。
🔍 为什么这样分工
安全员绝不能兼职接单（N3 独立、优先级最高）；经理绝不能亲自炒菜（N2 只编排不执行）。
决策与执行分离
，正是"打断分层（雷达>语音）"能在架构层落地的原因。

09
重点与易错点
⚠️ 三大经典易错
run_until_sensor 不是阻塞等待（异步：立即返回+完成走 state 话题）；start 服务返回 ≠ 任务完成（触发语义 vs 完成语义）；launch 只保证"启动尝试顺序"——N-grasp 启动慢于 N2 时靠
2s 自动重试兜底
，不要依赖启动顺序。
⚠️ 常见坑
现象 → 解法
以为 palletize 是"先抓后送"
未理解码垛取料位在流水线上 → 对照
scheduler_node.py
L8-L9 docstring 与 L98-L127：先 run_until_sensor 送料到取料位，等 sensor_blocked 再抓取
start 返回 = 完成
混淆两种语义 → grasp/start 与 run_until_sensor 都
立即返回
（触发），完成走 grasp/status 与 conveyor/state 话题
分不清 ExecuteProcess 与 Node
不了解 venv 依赖隔离 → voice 依赖 sherpa_onnx（仅 venv）、vision 依赖 cv2 4.11 必须直跑；scheduler/safety 仅标准接口用入口点
以为重试会堆积定时器
未看早退逻辑 →
_retry_grasp
先判
_pending_task is None
直接 return，成功重放后置 None 并 cancel 定时器（L154-L169）
以为 N3 只跟 N2 通信
漏看 C1/F10 → danger 广播发给 N2/N-grasp/N-conveyor 三方：流水线收到急停并调 /arm_controller/emergency_stop，抓取收到立即停止

接口才是连接件 → 必须标注 intent/speak/danger/grasp/start/run_until_sensor 等，与 EXP-03 接口清单呼应

📝 思考题 1
为什么 palletize 采用"run_until_sensor 立即返回 + 订阅 conveyor/state 感知完成"的异步方案，而不是同步阻塞等待？请结合 N2 需要实时响应 interrupt/danger 说明。
📝 思考题 2
