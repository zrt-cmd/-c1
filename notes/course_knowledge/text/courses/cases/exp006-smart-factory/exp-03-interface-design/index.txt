01
问题引入：接口对不上，联调全报废
两个小组并行开发：A 组写语音、B 组写调度。联调那天——
1
A 组往
/eai_factory/intent
发了
"开始装货"
（中文句子），B 组在等
"load"
（英文枚举）→
对不上暗号
2
A 组用话题发任务、B 组做成服务等调用 →
通信范式不一致
，谁也叫不醒谁
3
B 组任务做完了发了"完成"，A 组却在轮询另一个名字的话题 →
播报永远不响
4
解法：
先签契约再写代码
——五系列接口清单（名称/类型/方向/消息/语义）就是全项目的技术合同
💡 接口 = 契约
接口定义回答三件事：
谁发布、谁订阅（方向）
，
说什么语言（消息类型）
，
说完了算不算数（触发 vs 完成语义）
。三者都写进清单表，双方各自开发也不会跑偏——这就是"接口先行"的工程纪律。
02
原理通俗讲解：传菜条的写法与后厨暗号
餐厅的传菜条（接口）怎么写才不出错？三条生活经验直接对应三条设计规律：
✏️ 规律一：格式看内容
什么信息用什么格式
状态类（跑没跑、安不安全）用
String 枚举
（idle/running/sensor_blocked、safe/danger/recover）；布尔信号用
Bool
（interrupt/danger）；办手续用
Trigger
（回执 success+message）；坐标位姿用
PoseStamped
。看到新接口先猜类型，八九不离十。
📎 规律二：喊话 vs 立字据
话题异步、服务同步
"装货开始了"这种
叫一声人人听见
的用话题（intent/speak/status/danger）；"把这批货抓了并等你回话"这种
必须等回执
的用服务（start_load、grasp/start）。喊话不保证听到，立字据保证有回执。
🏷 规律三：触发 ≠ 完成
两段式确认
服务返回 success 只代表"
任务已受理
"（'load task triggered'），机械臂还在动；真正完成要等 status/state 话题通知。
预约餐厅拿到排队号（触发）≠ 菜已上桌（完成）
。
🧾 规律四：改单不改菜谱
yaml 表驱动映射
"装货"这个词对应哪个服务？写在 yaml 的 intents 段（load→/eai_factory/start_load）。
加个新意图 = 加三行配置
，一行代码不用动——后厨加菜只改菜单不改流程。
🧲 规律五：借来的工具贴标签
D 系列复用接口
pick/place/go_work/set_motor 这些是
复用包既有接口
（D 系列）——eai_factory 只调用不重写。清单表里标注"复用"，避免误以为是自家定义。
🔔 规律六：播报走固定文案
A2 speak 是唯一出口
所有对外播报（"装货完成"）都经 N2 发 A2 speak、由 N1 的 TTS 念出——
出口收敛到一个接口
，文案才管得住（R7）。

09
重点与易错点
⚠️ 三大经典易错
消息类型记混（记住"语义定类型"：状态 String、布尔 Bool、触发 Trigger、位姿 PoseStamped）；混淆触发与完成语义（start 即返 ≠ 任务做完，完成看 grasp/status 与 conveyor/state）；照抄文档不核代码（D1 差异就是教训，以代码为准）。
⚠️ 常见坑
现象 → 解法
service call 报 not available
对应节点未启动或服务名拼错 → 先
ros2 service list
查存在性；E1-E3 由调度器提供、F1-F5 由 conveyor 提供、grasp/start 由 grasp 提供
改了 yaml 坐标不生效
参数在节点启动时读取一次 → 修改后重启对应节点；运行中可
ros2 param get /eai_factory_grasp grasp.tasks.load.observe_pose
检查当前值
以为 mode 只影响抓取
mode（yaml L7）由 grasp 节点读取：debug 模式检测到目标后
等 /eai_factory/grasp/confirm
人工确认（grasp_node.py L295-L301），production 直接 pick；改 mode 需重启
清单漏掉完成语义接口
grasp/status、conveyor/state 漏记 → 漏掉它们就解释不了"装货完成"播报从哪来（闭环最后一环是 grasp/status → speak）
D 系列当自家接口
docs L58 注明"D 系列为复用现有接口" → 实现在 car1_arm_controller / car1_base_driver 等复用包，eai_factory 只调用不改
sort.place_pose 数值对不上
文档 D9 示例与 yaml 现值有差异（如 [0.1334,-0.1396,...] → [0.1434,-0.1296,0.2075,2.7283]）→ 正是"配置驱动、改配置不动代码"的活例，以 yaml 实际值为准
