02
核心原理：光如何变成话题——HSV 判灯与 NPU 检测双通道
把识别想成交通协管员：
他盯灯用"颜色直觉"（这盏灯发红光——色相对了就是红灯，亮不亮只是阈值问题），认标志用"图形记忆"（圆形蓝底带箭头=直行）。第一条通道
HSV 颜色分割
正对应"直觉"：RGB 三通道把亮度和颜色搅在一起，转到 HSV 后
H（色调）单独承载"是什么颜色"
——红灯 H≈0-10 或 170-180（红环抱 0°），绿灯 H≈35-85，黄灯 H≈20-35，各留 ±10 窗口吸收 LED 色偏与白平衡漂移；S、V 通道卡"够不够饱和、够不够亮"排除反光与暗影，再用开运算去掉标线反光的碎斑，取连通域最大者判定灯态。
第二条通道
YOLO + NPU
对应"图形记忆"：四类标志长得像（都是牌面），靠颜色会翻车——直行/转向是蓝底白图案，停车是红圈白底，注意行人是黄三角。yolov8n 在 PC 上训好 → 转
RKNN INT8
→ 塞进 C1 的
6 TOPS NPU
，前向推理吃掉大头 CPU；输出框经 NMS 去重后按置信度过滤，封装成
std_msgs/String
JSON 发
/traffic/sign
。两路话题合流，EXP-03 的状态机才有"灯态 + 交规牌"两本经。

PC 上用 1500+ 张四类增强数据（旋转/亮度/侧角）训 yolov8n → export ONNX → rknn-toolkit2 转 INT8（校准集 200 张）→ 拷贝到 C1 加载，
rknpu2_server

python3 src/export_rknn.py --model best.pt --quantize int8 --platform rk3588
python3 src/app.py --model models/traffic_sign.rknn --topic /ascamera_hp60c/color_image
# ⑤ 观察检测输出 / 端到端延迟
ros2 topic echo /traffic/sign
# {cls, conf, dist}
ros2 topic hz /traffic/sign
# ≥15Hz
验收标准（写入 s4 打卡）：
① 三态灯 20 轮 ×3 光照准确率 ≥95%；② 四类标志在 0.3/0.5/0.8m 三档距离均检出、置信度中位数 ≥0.6；③ 换光照 5 分钟内重标定完成并复测通过。
易错点：识别距离小于 0.3m 进近盲区白屏、忘记三帧稳定导致灯态抖动、INT8 校准集没覆盖夜晚帧。
HSV 为什么不直接用 RGB
V 变化会同时拉动 R/G/B；H 对亮度不敏感，换灯、过曝时更稳。
置信度阈值的两难
0.55 是起点：升→漏 (注意行人)、降→幻觉 (转向误报)；用 PR 曲线找拐点而非拍脑袋。
灯 vs 牌 谁先判
灯走 ROI 颜色（毫秒级），牌走 NPU（十毫秒级）；路口先看灯，灯绿再消费标志改道。
/traffic/* 为何用 String
跨节点接口越简单越稳：JSON 字段 cls/conf/dist 够 EXP-03/04 用，避免自定义 msg 的编译耦合。

08
常见问题
Q 红灯常被认成绿灯？
红 H 环抱 0°/180°：两个窗口都要开（0-10 与 170-180）；再把 S 下限提到 60 排除白反光。
Q 接近 0.3m 画面突然花？
HP60C 0.5m 近盲区边缘：识别机位保持 0.3~0.8m，别把相机怼到灯上标定。
Q /traffic/light 一直闪？
缺三帧稳定滤波，或曝光在频繁抖：锁定曝光参考帧 + 连续 3 帧一致才发布。
Q NPU 推理没生效还是 CPU 跑？
查 rknpu2_server 是否加载了 rknn 文件；日志无 "model loaded" 或延迟 >100ms 即掉回 CPU。
Q 换灯后全部失灵？
按验收流程 5 分钟重标定：三态各截一帧 → trackbar 重拖 → 存 hsv_config.yaml，别改代码。
Q 置信度调到多少合适？
以 PR 曲线拐点为锚，本沙盘经验值 0.55；四类样本不均衡时按"注意行人"召回率定下限。
Q 检测帧率掉到 5Hz？
NPU 被占或分辨率过大：640→416 降档；确认无其他模型进程抢占。
Q /traffic/sign 没消费方？
正常——EXP-01 阶段它只是生产者；EXP-03 状态机上线后才会被订阅，先用 echo 验收。
