01
问题引入：告警之外，还要会"对话"和"复核"
前面实验已让系统"看得见、判得准、喊得响"，但两根刺还扎着：一是
误报
——老人弯腰系鞋带被判跌倒，半夜反复报警把全家吵醒；二是
安抚缺失
——只会重复一句硬邦邦的告警语。理想监护应该：跌倒时
先多问一句确认
（VLM 看图复核），无事时能
陪老人聊两句
（LLM 闲聊），且全程
不出家门、不上传云端
。
1
端侧 NPU 跑 Qwen3.5-0.8B：对话闲聊、语音安抚、上下文记忆
2
滑动窗口把多轮历史拼成一条，治愈"系统记不住我刚才说的话"
3
VLM 复核：跌倒候选帧交给"会诊医生"再看一眼，降低误报
4
安全优先的并存路由：告警 > 询问 > 播报 > 闲聊，永不抢麦
💡 一个类比
整套 LLM/VLM 链路像给家里请了一位
住家护工
：会陪聊（对话）、记得你刚说过什么（记忆窗口）、看到可疑情况会先凑近看一眼再喊人（视觉复核）—— 而且这位护工
从不把家里的事说出去
（端侧推理）。
02
原理通俗讲解：端侧大脑、记忆条与会诊医生
RKLLM 端侧推理
把"大块头"压缩进工控机的书包
Qwen3.5-0.8B 用 w4a16 量化后权重仅约 0.4G，带激活共约
1.5G
的 .rkllm 文件，由 ctypes 直接加载
/usr/lib/librkllmrt.so
塞进 NPU —— 像把整本词典压缩成口袋书，推理全在板上完成，一个字节都不外发。
滑动窗口
手心上贴一张"记忆便利贴"
RKLLM 的 get_last_input() 每次只吐最后一条 user 消息，天然健忘。LLMChat 于是取
[-2×max_history:] 条历史
拼成「用户：…\n小飞：…」的对话记录，前面加上"请根据上下文自然回答最后一句"的指示 —— 便利贴只留最近几条，旧的撕掉（max_history=6，存两层各 12 条即截断）。
流式 SSE
打字机式的回信
回调 callback_impl 逐 token 累积 global_text，Flask 端点以
data: {...delta.content...}
逐段下发、以
data: [DONE]
收尾，LLMClient 用纯标准库 urlopen 消费 —— 用户看到回答"一个字一个字蹦出来"，而不是等全文憋 30 秒。客户端 SSE 解析失败还会自动降级非流式（chat.py L56-L59）。
VLM 复核
喊人之前先看一眼照片
RKLLMVisionJudge 懒加载：收到请求才花 10-60s 载入 1.3G 视觉模型。图片缩到 448×448 → 视觉编码器 →
196=(448/32)² 个 patch、每片 1024 维
嵌入，以 <img>…</img> 标记塞进多模态接口；回答三分类 fall/not_fall/uncertain（含"是"不含"否"→0.8 等规则）。
🔔 人文关怀与隐私底线
对话与图像全在
端侧
处理，不依赖公网云 —— 老人的居家影像与言语不出户。vlm.enabled
默认 false
不是偷懒：LLM 1.5G + VLM 1.3G ≈ 3.0G+，2G/4G 内存的板子慎开；先把核心监护跑稳，按硬件余量再开复核。
03
关联知识点：LLM 服务 · 滑动窗口 · VLM 复核
知识点
内容
源码锚点
llm_server RKLLM 初始化
ctypes.CDLL('/usr/lib/librkllmrt.so')；模型 Qwen3.5-0.8B_w4a16_g128_rk3576.rkllm ≈1.5G；采样 temperature 0.8 / top_p 0.9 / top_k 1（贪心）/ repeat_penalty 1.1 / max_context_len 4096，可按请求覆盖；callback_impl 逐 token 累积 global_text 即天然流式
llm_server.py L15-L16（CDLL）、L213-L232（回调）、L259-L272（采样参数）、L617-L621（按请求覆盖）
Flask OpenAI 兼容层
GET /v1/models 返回模型清单；POST /v1/chat/completions 输出 SSE：data: {...delta.content...} → data: [DONE]；lock+isBlocking 串行化 RKLLM 推理，撞上并发即 503 server busy
llm_server.py L584-L596（/v1/models）、L598-L690（/v1/chat/completions）
2.1.4 滑动窗口拼接
get_last_input() 只取最后一条新增 user → LLMChat 取 [-2*max_history:] 历史拼「用户：xxx\n小飞：xxx」单条 content，前缀「以下是一段对话记录，请根据上下文自然回答最后一句，不要复述记录」；存储层 >2*max_history+8 截断；reset 全清
chat.py L36-L46（拼接+指示）、L43（窗口截断）、L68-L69（存储截断）、L139-L140（reset）；llm_client.py L59-L145
server_manager 生命周期
pick_free_port 从 8080 起 connect_ex 探测 20 个；_port_open+_models_ok GET /v1/models 判断可复用；Popen 拉起日志隔离 runs/logs/llm_server.log；就绪轮询每 2s、超时 120s；stop() terminate→wait(5)→kill，只杀自己拉起的
server_manager.py L33-L40、L42-L53、L85-L99、L106-L110、L113-L125
2.1.5 VLM 复核
VisionJudge 协议 + FakeVisionJudge 恒 uncertain 兜底；RKLLMVisionJudge 懒加载 _load 10-60s；PROMPT「图中的人是否摔倒了？只回答'是'或'否'或'不确定'，然后写一句理由。」；三分类含"是"不含"否"→fall(0.8)/含"否"→not_fall(0.8)/不确定或报错→uncertain(0.5 或 0.0)；异常全捕获返 uncertain 主流程不崩；config vlm.enabled 默认 false
vision_judge.py L23-L25（PROMPT）、L34-L44（协议+Fake）、L243（懒加载）、L388-L399（异常兜底）；config/fall_config.yaml L12-L16
并存与优先级
告警/播报/闲聊共用 plughw:3,0 分时发声；优先级 ALERT＞ASK＞SPEAKING＞LLM 闲聊（安全设计非 bug）；monitor 三接口 on_kws / on_asr / has_ask_session 是耦合点
fall/monitor.py（三接口注册）；server_manager 端口避让 llm.server.port

09
重点与易错点
system_prompt 不要乱改
（config L149）：它定义了"小飞"的人格与回答边界
窗口有两层截断
：取用 [-2×max_history]、存储 >2×max_history+8 —— 调 max_history 会同时影响两者
VLM 复核是"辅助第二意见"
：uncertain 是合法答案，主流程靠它兜底而不是被它卡死
优先级不可倒挂
：闲聊永远压不过 ALERT/ASK，否则复核/告警会被长回复堵死
现象
原因
解决
启动超过 30s 甚至卡死
model_path 错（config L145）/ NPU 驱动异常 / 模型与固件不匹配
核对路径与文件 1.5G；cat /sys/kernel/debug/rknpu/version 查驱动
问"我叫什么名字"答不上
没走 LLMChat 拼接（直喂 get_last_input）/ 历史超出窗口被截
确认走 chat() 全链路；检查 max_history 与是否误 reset
OOM / 整机卡死
LLM 1.5G + VLM 1.3G ≈ 3.0G+，2G 内存板撑不住
2G 板保持 vlm.enabled=false；4G 板开前 free -h 预算
报 503 server busy
RKLLM 推理串行锁，前一个请求未返回
属设计预期；客户端 chat.py L56-L59 会自动降级非流式重试
8080 端口腾不出来
上次 llm_server 残留 / 被无关服务占用
ss -tlnp 找 pid；pkill -9 -f llm_server；或靠 pick_free_port 避让
vlm_demo 一直 uncertain
图片模糊、裁剪没带全人体（crop_margin 太小）/ 模型懒加载未完成
换 testdata/fall_1.png 标准图对照；等待 _load 完成再看耗时日志
忘了早期对话内容
滑动窗口本性：老条目按 L43/L68 两层截断出窗
属正常行为；确需长期记忆要另做持久化（本课不涉及）
端口探测逻辑排错难
_port_open+_models_ok 要"既在听、又应答 /v1/models"
用 curl /v1/models 复刻探测条件，凡 200 且含模型名才判可复用
