fall_config.yaml 配置详解：系统唯一的"总闸"
整个 elderly_companion 只认一份 YAML：
config/fall_config.yaml
，共十四段，管着从模型路径、检测阈值、状态机时间参数到串口设备、LLM 服务端口的一切。本实验吃透
config_schema 必填/可缺省双轨
、
CLI > yaml > 代码默认
三层覆盖优先级，学会用
env_check
一键体检七个依赖库、模型文件与串口设备，做到"改参数不动代码、动代码必过自检"。

01
问题引入：改一个阈值为什么要惊动全系统
课堂上最常见的事故：同学把"躯干角 50°"直接写进状态机源码里测试 —— 结果代码里 50、YAML 里 50、注释里 45，三处不一致，谁也说不清线上到底用的哪个。工程化的答案是：
所有可调量只住在配置文件里
。
1
阈值散落源码 → 改一次要全文搜索，漏一处就是隐性 bug
2
集中到 fall_config.yaml → 调参 = 改一行，重启即生效，还可 git diff 审查
3
再加 config_schema 校验 → 键名拼错、必填缺失在启动时立刻报错，不带病运行
4
最后由 env_check 把关 → 依赖库、模型文件、串口设备逐一探测，EXIT 0 才准开工
💡 一个类比
配置文件像家里的
配电总闸 + 分路标签
：哪里该通电、多少安培（阈值）都写在面板上。总闸不清晰，谁都不敢动线路。
02
原理通俗讲解：参数的三层来源与"双轨制"
同一个参数可能来自三个地方，
优先级从高到低
：
第 1 优先
命令行 CLI 参数
如
--score-thr 0.4 --log-level DEBUG
：一次性实验覆盖，不落盘、不污染文件，跑完即失效。适合"今天临时试一个值"。
第 2 优先
fall_config.yaml
持久化的正式值：团队共享、随版本走。适合"这个项目的正式参数"。CLI 没给的键，全部以这里为准。
第 3 优先
代码内默认值
config_schema 的兜底：yaml 没写、CLI 也没给的
可缺省键
，自动填默认值，保证程序永远拿得到值。
而 config_schema 本身是
双轨制
：
轨道
schema 写法
缺失时的行为
例子
纯 type（必填）
type: str
（无 default）
yaml 里没写 → 启动直接
config error: missing key
detect.model_path 等路径类键
(type, default)（可缺省）
带默认值
yaml 没写 → 自动填默认，程序照常跑
detect.score_thr、state.angle_thr
🔔 隐患坑：schema 有默认不等于 YAML 是活键
典型如
session.wake_words
：schema 给了默认值（可缺省轨道），于是 yaml 里没写时也会"正常启动"—— 但你以为在改唤醒词、实际生效的是 schema 默认。
要改的键必须显式写进 yaml
，别依赖兜底。

🙋 调参伦理
把 score_thr 调高"少误报"，代价是远处/遮挡的老人被漏检；调低则误报增长。调参不是刷指标，是
在"漏救"与"骚扰"之间找平衡
—— 每次改动都记录理由。

3

4

口述三个设备/端口分工（六麦 ACM0、告警 USB0、雷达 USB1；LLM 8080、MJPEG 8088）并复验

🔍 端口备忘
/dev/ttyACM0
= XFM 六麦硬件唤醒（speech 段）；
/dev/ttyUSB0

= 毫米波雷达，告警不走它。硬件插拔后枚举号可能漂移，报错先

⚠️ 常见坑
现象 → 解法
键名拼错
启动
config error: missing key
→ 核对 schema：改 yaml 键名而不是改 schema
误把"可缺省"当"没生效"
改了概念却没改 yaml（session.wake_words 典型）→ 要改的键显式写进 yaml
CLI 参数顺序/拼写错
--sore-thr 静默或报错 → 每次跑完看日志里的实际生效值
串口张冠李戴
告警没反应，插的是 USB1（雷达）→ alert.port 对准 USB0
端口混用
curl 8088 找 LLM / MJPEG 8088 找 llm → LLM 在
8080
（/v1/models），预览流在 8088
体检当安装器
MISSING 后等它自动修 → env_check 只读，依赖需按讲义自行安装

❓ 排障思路
先问参数从哪来

📝 思考题 1
实验课上你临时要试 score_thr=0.4，正式项目值是 0.25。用哪种方式覆盖最稳妥？如果下一位同学接手，如何保证他不会"误以为"项目值已改成 0.4？写出你的操作与沟通清单。
📝 思考题 2
config_schema 给 session.wake_words 提供了默认值，但讲义仍强调"要改就必须显式写进 yaml"。请推演一次事故：同学 A 只在心里把唤醒词改成"小飞小飞"，现场系统却毫无反应 —— 用"双轨制 + 三层优先级"解释这个现象的完整链条。
