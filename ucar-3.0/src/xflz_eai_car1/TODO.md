## P0 - 校准优化（提升精度）

### 0.1 舵机 per-servo offset 补偿

**背景**：Level 3 实测发现 ID1（大臂）+22~24 PWM 系统性偏移，ID2（小臂）+13~14 PWM 偏移，末端位置误差 5~8mm。

**当前状态**：视觉闭环已能补偿，但在无视觉的纯 IK 场景下会有明显偏差。

**优化方案**：
- 在 `arm/kinematics/kinematics/transform.py` 的 `SERVO_CONFIG` 中添加 per-servo offset
- 或用舵机协议 `#001PSCK!` 命令硬件校中位（一次性写 EEPROM）

**预期效果**：末端位置误差 5-8mm → 1-2mm

**验证方式**：
```bash
python3 arm/kinematics/kinematics/interactive_ik_test.py --direct
# 测试点 (0.22, 0.0, 0.15) 用尺子实测
```

---

### 0.2 IMU 静止零偏在线估计

**背景**：BMI088 静止时 gyro_z 有 ±0.04 rad/s 零偏，长时间 SLAM 会累积漂移。

**当前状态**：AMCL 兜底能保证 map→base_footprint 稳定，odom 帧漂移不影响导航。

**优化方案**：在 `odom_publisher_node.py` 增加零偏估计逻辑：
- 静止状态检测（cmd_vel = 0 持续 2 秒）
- 平均此期间的 gyro_z 作为在线 offset
- 后续持续从 IMU 数据中扣除

**预期效果**：静止 5 分钟 yaw 漂移从 5° → <1°

**触发条件**：仅在需要长时静止仍保持 odom 帧稳定时才做

---

### 0.3 编码器闭环里程计

**背景**：ROS odom 是**开环积分** cmd_vel（不读编码器），不同速度下加速/减速段占比不同，引入非线性误差（见 tutorial 3.0.1.1）。

**当前状态**：单速度标定误差 <5%，SLAM 够用。

**优化方案**：
- 固件端上报编码器实测轮速
- ROS 端 odom 改用编码器反馈而非命令积分
- 需 Windows Keil 修改 STM32 固件

**预期效果**：多速度下里程计精度统一（不再依赖标定速度）

**依赖**：需要开发板厂家配合修改固件

---

### 0.4 IMU SM 矩阵校准

**背景**：BMI088 三轴之间存在非正交性和 scale 误差，长时 SLAM 精度要求极高时需要。

**当前状态**：单轴 scale 已通过转动法校准（1.01×）。

**优化方案**：使用高精度转台采集数据，估计完整 SM 矩阵（3×3）。

**触发条件**：仅在长距离 SLAM（>50m）出现累积漂移时才做

## P1 - 视觉抓取精度提升

### 1.1 深度盲区解决（HP60C < 0.5m）

**背景**：HP60C 深度相机在 0.5m 内基本无有效深度，eye-in-hand 俯视抓取距离恰好在盲区。

**当前状态**：Level 5 通过多次检测取稳 + 观察姿态较高（z=0.22m）勉强避开盲区。

**优化方案**（三选一）：
1. **平面投影**：假设物体在已知平面（z=table），用 RGB + 内参 + TF 反算 3D 坐标（不用深度）
2. **换观察姿态**：机械臂抬得更高（z=0.30m），把物体推到远距有效区
3. **物体垫高**：物理方式解决

**触发条件**：需要抓取 <30mm 小物体或深度采样点数不足时

**注**：navigation_grasp_transport.py 曾尝试方案1（平面投影），因 TF 定义问题失败，最终改回深度反投影。若要重做，需要先验证 URDF 中相机 TF 的完整性。

---

### 1.2 HSV 阈值自适应

**背景**：不同光照下红色 HSV 阈值需要手动调整。

**优化方案**：
- 启动时采样背景图，自适应确定阈值
- 或用 ColorThresholder GUI 交互式标定

**触发条件**：换光照环境后抓取失败率升高时

---

### 1.3 多物体分类抓取

**背景**：当前只识别单一红色方块。

**优化方案**：
- HSV 阈值改为**参数列表**（红/绿/蓝）
- 检测到多个候选后按颜色分类
- 不同颜色放到不同 place_target_arm

**扩展点**：
- `navigation_grasp_transport.yaml` 增加 `target_colors: [red, green, blue]`
- 每种颜色配置 HSV 范围 + 对应放置点

---

### 1.4 姿态优化（非顶部抓取）

**背景**：当前所有抓取都是 pitch=π（垂直向下），只适合方块顶部抓取。

**优化方案**：
- 检测物体朝向（PCA on contour）
- 根据物体朝向调整夹爪角度
- 支持侧面抓取（pitch = π/2）

**触发条件**：抓取圆柱、长条形物体时

---

### 1.5 深度学习检测（YOLO 替代 HSV）

**背景**：HSV 检测在复杂背景下容易误检。

**优化方案**：
- 集成 YOLOv8 nano 模型（板端 CPU 推理）
- 训练识别常见物体类别
- 保留 HSV 作为 fallback

**触发条件**：抓取类别扩展 >5 种时

## P2 - 导航优化

### 2.1 lidar_filters 集成

**背景**：Lidar 装在车前端，向车尾扫描时可能扫到自身（外壳/支架/相机）。

**当前状态**：需实测确认是否有自身残影。

**排查步骤**：
```bash
ros2 launch car1_navigation navigation.launch.py
# RViz 加 LocalCostmap 显示
# 机器人静止于空旷处，观察 footprint 周围是否有持续红色 cell
```

**优化方案**（发现残影再做）：
- 启用 `lidar.launch.py` 的 `ignore_array` 参数屏蔽车后扇区
- 或引入 `laser_filters` 节点（会增加 IPC 延迟）

---

### 2.2 MPPI 参数优化

**背景**：MPPI batch_size=2000 × time_steps=56 在 RK3576 上可能 CPU 吃满。

**排查步骤**：
```bash
ros2 launch car1_navigation navigation.launch.py
htop  # 看 controller_server CPU
ros2 topic hz /local_costmap/costmap_updates  # 应稳定 20Hz
```

**优化方案**（超过 90% 单核时）：
- batch_size: 2000 → 1000
- 或 batch_size 1500 + time_steps 40

**当前状态**：需实测评估

---

### 2.3 更大地图

**背景**：当前测试地图 slam_map.pgm 只有 29×38 像素（1.45m × 1.9m），太小。

**优化方案**：重新建一个至少 4×4 米的地图（80×80 像素以上）

**建议**：完成 Level 5.7 后建一个覆盖整个抓取工作区的地图

---

### 2.4 动态 costmap 更新

**背景**：抓取后物体位置改变，但 costmap 中原位置仍显示为障碍物。

**优化方案**：
- 抓取完成后触发 `/global_costmap/clear_around_robot`
- 或在 costmap 中添加抓取区域为可通行区

**触发条件**：物体放置点位于原抓取区附近时

## P3 - 任务扩展

### 3.1 多点巡逻抓取

**背景**：当前只有一个抓取点和一个放置点。

**优化方案**：
- 扩展 `navigation_grasp_transport.yaml`：
  ```yaml
  pick_poses:  # 多个抓取点
    - [x1, y1, yaw1]
    - [x2, y2, yaw2]
  place_poses: # 多个放置点
    - [x1, y1, yaw1]
    - [x2, y2, yaw2]
  ```
- 主节点循环访问所有点
- 支持中途暂停/恢复

**预计工作量**：2-3 小时

---

### 3.2 语音 / Web 控制界面

**背景**：当前只能通过 ROS 服务调用触发任务。

**优化方案**：
- Web 界面：Flask + WebSocket 显示状态 + 触发按钮
- 语音：接入语音识别 SDK（如讯飞、百度）

**参考**：`test/camera_web_viewer/` 已有 Web 服务框架

---

### 3.3 抓取失败重试

**背景**：当前抓取失败直接进入 FAILED 状态。

**优化方案**：
- 抓取后验证是否真的夹住（可通过舵机电流或深度图）
- 失败时自动重试（最多 3 次）
- 重试时可微调抓取位置

**验证方式**：
- 舵机 5（夹爪）电流反馈
- 抓取后再检测一次，看物体是否消失

---

### 3.4 小范围平移搜索

**背景**：当前旋转搜索只覆盖 ±45° 视野，物体在机器人正下方或后方时找不到。

**优化方案**：旋转失败后，尝试小范围平移（前进/后退 10cm）再搜索

**扩展 `search_angles_deg` 为 `search_pattern`**：
```yaml
search_pattern:
  - {type: rotate, angle: 0}
  - {type: rotate, angle: 30}
  - {type: rotate, angle: -30}
  - {type: translate, x: 0.1}  # 前进 10cm
  - {type: rotate, angle: 0}
```

---

### 3.5 抓取后返航路径优化

**背景**：抓取后直接调用 Nav2 返回，可能选择较长路径。

**优化方案**：
- 记录去程路径，返程用同一路径（避免绕远）
- 或在 costmap 中给"抓取物"周边区域加 preferred cost
